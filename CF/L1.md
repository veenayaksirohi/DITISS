## 1. Core Definition

**Digital Forensics / Computer Forensics**

- Digital forensics is the application of scientific methods to identify, acquire, preserve, examine, analyze, and report digital evidence from electronic devices for use in legal proceedings.
- Focus: integrity of data + strict chain of custody so evidence is admissible in court.

**Goals:**
- Identify cyberattacks and intrusions.
- Determine extent and impact of damage.
- Recover and preserve digital evidence.
- Support criminal, civil, and internal investigations.

***

## 2. Types of Digital / Cyber Forensics

### 2.1 Network Forensics
- Deals with **monitoring, capturing, and analyzing network traffic**.
- Evidence sources: PCAPs, firewall logs, router/switch logs, IDS/IPS alerts.
- Used to detect intrusion methods, lateral movement, data exfiltration, and C2 (malware) communication.

### 2.2 Disk Forensics
- Investigation of **storage media** like HDDs, SSDs, USBs, memory cards.
- Recovers deleted/hidden files, file system artifacts, user activity, logs.
- Always work on **forensic images**, never on original disk (preserve integrity).

### 2.3 Memory Forensics
- Focus on **volatile memory (RAM)**.
- Captures running processes, network connections, encryption keys, in‑memory malware/fileless malware.
- If system is powered off, RAM contents are lost.

### 2.4 IT Forensics
- Forensics across:
  - Distributed systems
  - Non‑distributed/standalone systems
  - Computer networks
- Common in corporate investigations and incident response.

### 2.5 Live Forensics
- Performed **while the system is powered on and incident is ongoing**.
- Focus on volatile evidence: RAM, active processes, open files, active network connections.
- Used when shutting down would destroy crucial evidence (e.g., in‑memory malware).

### 2.6 Offline / Post‑Mortem Forensics
- Performed **after system shutdown**.
- Activities: disk imaging, file system analysis, deleted file recovery, timeline creation, artifact analysis.
- Usually on **forensic images** instead of original media.

### 2.7 Data Forensics
- Focus on **data itself**, especially:
  - Integrity and validation
  - Application logs
  - Database investigations
- Used for data tampering, fraud, transaction manipulation cases.

***

## 3. Objectives of Disk Forensics

- Identify intrusion methods and entry points.
- Determine attacker activities on the system.
- Assess extent of damage and data loss.
- Recover deleted/hidden/malicious data.
- Preserve evidence in forensically sound manner.
- Produce clear, legally admissible reports.

***

## 4. Chain of Custody (CoC)

**Definition:**
- Chain of Custody is the **complete, documented history** of evidence from collection to presentation in court, proving that evidence is authentic, unaltered, and traceable.

**Ensures:**
- Who collected evidence.
- When and where it was collected.
- Who accessed/handled it and why.
- Evidence integrity and continuity.

**If CoC is broken → evidence may be ruled inadmissible in court.**

### 4.1 Steps in Chain of Custody

1. **Create Evidence Record**
   - Case ID
   - Evidence ID
   - Description
   - Date & time
   - Collector / Investigator name
   - Hash values (MD5/SHA‑256)

2. **Maintain Transfer Log**
   - From → To
   - Date & time
   - Purpose of transfer (e.g., analysis, storage)

3. **Secure Storage**
   - Read‑only media
   - Evidence lockers
   - Access‑controlled rooms
   - Tamper‑evident packaging

***

## 5. Principles / Best Practices of Digital Forensics

### 5.1 Preservation of Evidence
- Protect from alteration, corruption, or damage.
- Use **hardware write blockers** or read‑only mounts.
- Never analyze original media; always use a copy.

### 5.2 Hashing
- Used to verify the **integrity** of evidence and images.
- Algorithms: MD5, SHA‑1, **SHA‑256 (preferred)**.
- If hash of original and image match → accepted as exact bit‑by‑bit copy.

Example:
SHA256(Original disk) = SHA256(Forensic image)

### 5.3 Maintain Chain of Custody
- Log collection, transfers, examinations, storage, and access all along the lifecycle.

### 5.4 Forensic Imaging
- Always create a **forensic image (bit‑by‑bit copy) before examination**.
- Original media is preserved; all work is done on the image.

### 5.5 Documentation & Reproducibility
- Record:
  - Tools and versions
  - Commands / procedures used
  - Hash values
  - Findings and interpretations
- Another examiner should be able to reproduce the same results.

### 5.6 Legal Compliance
- Follow:
  - Organizational policies
  - National cyber laws (e.g., IT Act 2000)
  - Standard forensic procedures and court rules

## 6. Forensic Imaging

**Definition:**
- Forensic imaging is creating an **exact, bit‑by‑bit, sector‑by‑sector copy** of a storage device, including active data, deleted data, unallocated and slack space.

**Includes:**
- All visible files and folders.
- Deleted data still present on disk.
- Unallocated and slack space.
- File system metadata.

### 6.1 Image Formats

- **RAW / DD:** Uncompressed raw bitstream, widely supported, large size.
- **E01 (EnCase Evidence Format):** Compressed, supports metadata, integrity checks, case details, widely accepted in courts.
- **AFF (Advanced Forensic Format):** Open source, supports compression, encryption, stores data + metadata.

### 6.2 E01 Features
- Compression to save space.
- Stores case info, examiner details, timestamps.
- Integrity checks (hashes).
- Standard in many legal investigations.

***

## 7. FTK Imager – Procedure

1. **Open FTK Imager**
   File → Create Disk Image.

2. **Select Source**
   - Physical drive / Logical drive / Existing image / Folder.

3. **Choose Image Type**
   - Select **E01 (recommended)** for investigations.

4. **Enter Evidence Information**
   - Case number, evidence number, description, examiner name, notes (helps CoC).

5. **Select Destination**
   - Save image on different physical disk than source.

6. **Enable Verification**
   - Enable "Verify image after creation".
   - Calculate MD5 and SHA‑1/SHA‑256 hashes.

7. **Start Imaging**
   - Tool creates image, calculates hashes, verifies integrity, and generates logs.

## 8. File Systems in Forensics

### 8.1 Linux: EXT2 / EXT3 / EXT4
- **EXT2:** No journaling, older.
- **EXT3:** EXT2 + journaling (better reliability).
- **EXT4:** Larger volumes/files, better performance, journaling.

### 8.2 NTFS vs FAT32

| Feature         | NTFS                           | FAT32                      |
|-----------------|--------------------------------|----------------------------|
| Journaling      | Yes                            | No                         |
| Security (ACLs) | Supports permissions, ACLs     | No native permissions      |
| Max file size   | Very large (theoretical TBs)   | 4 GB                       |
| Reliability     | Higher (journaling)            | Lower                      |
| Typical use     | Windows system drives          | USB drives, legacy systems |

***

## 9. Logical vs Physical Acquisition

| Aspect             | Logical Acquisition                    | Physical Acquisition                      |
|--------------------|----------------------------------------|-------------------------------------------|
| What is copied     | Selected files / partitions            | Entire disk (all sectors)                 |
| Speed              | Faster                                 | Slower                                    |
| Deleted data       | Usually missed                         | Included (if still on disk)               |
| Hidden areas       | Often missed                           | Included                                  |
| Forensics use      | Limited, when only certain data needed | Preferred standard in full investigations |
| Relation to images | Often "logical images"                 | Physical / full forensic images           |

Physical acquisition + forensic imaging is the **forensic best practice** for maximum evidence.

## 10. Timestamps (MAC Times)

- **M** – Modified time
- **A** – Accessed time
- **C** – Created / Changed (depends on OS and file system)

Used to:
- Build timelines
- Correlate attacker actions
- Reconstruct incident sequence

***

## 11. Computer Crime vs Unauthorized Activity

**Computer Crime**
- Any illegal act involving computers/networks (e.g., hacking banking system).
- Punishable under cyber laws.

**Unauthorized Activity**
- Violates policy/acceptable use, may not be criminal (e.g., installing pirated software at office).
- Usually leads to disciplinary action; sometimes overlaps with crime.

***

## 12. Cyber Laws

- **IT Act 2000 (India):** E‑commerce, digital signatures, cyber offences.
- **GDPR (Europe):** Data protection and privacy.
- **HIPAA (USA):** Health data privacy.

Also includes laws on:
- Hacking, unauthorized access, identity theft, phishing, malware distribution.

## 13. Forensic Investigation Process (6 Stages)

1. **Identification** – Locate potential sources of evidence (disks, USBs, emails, cloud, logs).
2. **Preservation** – Isolate system if required; prevent alteration; use imaging and write blockers.
3. **Collection** – Acquire data in forensically sound manner (FTK Imager, EnCase, etc.).
4. **Examination** – Filter relevant data, recover deleted files, examine logs and artefacts.
5. **Analysis** – Reconstruct events, correlate artefacts, link actions to users/attackers.
6. **Presentation** – Prepare clear, legally acceptable report; may provide expert testimony.

Aligned with NIST SP 800‑86.

## 14. Need for a Digital Forensics Investigator

**Why needed:**
- Rise in cybercrimes: hacking, phishing, ransomware, insider threats.

- Legal and regulatory compliance (IT Act, GDPR, etc.).

**Key Skills:**
- Good understanding of OS (Windows, Linux, mobile).
- Networking and protocols basics.
- Hands‑on with tools: FTK, EnCase, Autopsy, Volatility, etc.
- Knowledge of legal procedures and reporting.
- Strong analytical and documentation skills.
