# Scenario 3: RRAS with VPN (PPTP) Lab

## Objective

* Configure **RRAS VPN Server** on Windows Server.
* Machine A connects to Windows Server using **PPTP VPN**.
* Observe network traffic **with VPN** and **without VPN** using `tcpdump` on the Debian machine.
* Understand how VPN encrypts traffic.

# Test Without VPN

Disconnect VPN.

From Machine A

```
ping 192.168.50.101
```

tcpdump output shows

```
Source IP      = 192.168.40.101

Destination IP = 192.168.50.101
```

ICMP packets are visible.

Anyone on the path can inspect the traffic.

---

# Test With VPN

Connect VPN.

Ping again

```
ping 192.168.50.101
```

Now tcpdump shows

```
Source = VPN Endpoint

Destination = VPN Endpoint
```

Instead of normal ICMP packets, you will mainly observe **GRE (Generic Routing Encapsulation)** packets (used by PPTP) between the VPN client and VPN server. The original ICMP payload is encapsulated inside the VPN tunnel, so intermediate devices cannot directly inspect it.

## Key Learning Points

* Without a VPN, traffic from **Machine A → Windows Server → Debian** is plain routed IP traffic and ICMP packets can be observed on the network.
* With a PPTP VPN, a secure tunnel is established between Machine A and the Windows Server. The original packets are encapsulated (typically inside GRE), so intermediate devices see the tunnel traffic rather than the original ICMP packets.
* RRAS acts as both the VPN server and the router between the two LAN segments.
* The VPN client automatically receives an IP address from the RRAS static address pool when the connection is established.
