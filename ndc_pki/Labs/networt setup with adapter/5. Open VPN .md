# OpenVPN Lab Notes (Point-to-Point VPN)

## Lab Scenario

| Machine   | Operating System | IP Address        | Role           |
| --------- | ---------------- | ----------------- | -------------- |
| Machine 1 | Debian Linux     | `192.168.229.144` | OpenVPN Server |
| Machine 2 | Windows          | `192.168.0.220`   | OpenVPN Client |

### Objective

* Create a VPN tunnel between a Debian server and a Windows client.
* Verify communication through the VPN tunnel.
* Compare traffic inside the VPN tunnel and outside the tunnel using `tcpdump`.

# Server Configuration (Debian)

## Step 1: Install OpenVPN

```bash
sudo apt update
sudo apt install openvpn -y
```

---

## Step 2: Create Configuration File

```bash
vi server.conf
```

Add:

```conf
proto udp
port 1194

dev tun

auth none
cipher none

ifconfig 10.8.0.1 10.8.0.2

verb 3
```

### Configuration Explanation

| Parameter     | Description                                   |
| ------------- | --------------------------------------------- |
| `proto udp`   | Uses UDP protocol (faster than TCP for VPN).  |
| `port 1194`   | Default OpenVPN port.                         |
| `dev tun`     | Creates a Layer-3 (IP) tunnel interface.      |
| `auth none`   | Disables packet authentication (Lab only).    |
| `cipher none` | Disables encryption (Lab only).               |
| `ifconfig`    | Assigns VPN adapter IPs to server and client. |
| `verb 3`      | Moderate logging level.                       |

---

## Step 3: Verify Network Interfaces

```bash
ip -br -c a
```

Before starting OpenVPN, only physical interfaces should appear.

Example:

```text
lo
ens33
```

---

## Step 4: Start OpenVPN Server

```bash
sudo openvpn --config server.conf
```

> **Note:** Keep this terminal running.

---

## Step 5: Verify Tunnel Interface

Open another terminal.

```bash
ip -br -c a
```

Now a new interface appears.

Example:

```text
tun0    UNKNOWN   10.8.0.1/32
```

This confirms that the VPN tunnel adapter has been created.

# Client Configuration (Windows)

## Step 1: Install OpenVPN

Install the OpenVPN client.

After installation:

* A virtual TAP/TUN adapter is added automatically.
* OpenVPN executable is typically located in:

```text
C:\Program Files(x86)\OpenVPN Technologies\openvpn client\
```

or

```text
C:\Program Files(x86)\OpenVPN Technologies\openVPN client\
```

depending on the version.

---

## Step 2: Create Client Configuration

```
Crearte configuration file at 

C:\Program Files(x86)\OpenVPN Technologies\openVPN client\core\
```
Create any file with a **`.conf`** extension.

Example:

```text
client.conf
```

Contents:

```conf
remote 192.168.229.144

proto udp
port 1194

dev tun

auth none
cipher none

ifconfig 10.8.0.2 10.8.0.1

verb 3
```

### Note

Server IP in the `remote` directive must be the **Debian server's physical IP**.

Example:

```conf
remote 192.168.229.144
```

> Your notes had `192.168.80.130`, which should be replaced with the actual server IP for this lab.

# Step 3: Connect to VPN

Open **Command Prompt**.

Go to the OpenVPN binary directory.

Example:

```cmd
cd "C:\Program Files x(86)\OpenVPN Technologies\core\"
```

Run:

```cmd
openvpn.exe --config "C:\path\to\client.conf"
```

If successful, the VPN tunnel will be established.

# Verify VPN Connection

## Before Connecting

Try pinging the VPN adapter:

```cmd
ping 10.8.0.1
```

Result:

```text
Request timed out
```

because the tunnel is not established.

---

## After Connecting

Ping again:

```cmd
ping 10.8.0.1
```

Result:

```text
Reply from 10.8.0.1
```

The VPN tunnel is now active.

# Packet Capture using tcpdump

On the Debian server:

Capture ICMP packets on the physical interface (replace `ens33` with your interface name):

```bash
sudo tcpdump -i ens33 icmp
```

---

## Test 1: Ping VPN Adapter

```cmd
ping 10.8.0.1
```

### Observation

* Ping succeeds.
* **No ICMP packets** appear on `ens33`.

Reason:

The ICMP packet exists **inside the VPN tunnel**. On the physical interface, the original ICMP is encapsulated inside UDP packets, so `tcpdump` filtering for ICMP on `ens33` will not display it.

---

## Test 2: Ping Physical Server IP

```cmd
ping 192.168.229.144
```

### Observation

* Ping succeeds.
* ICMP packets are visible in `tcpdump`.

Reason:

The ping is sent directly over the physical network, so ICMP packets are visible.

# Key Viva Questions

### What is OpenVPN?

OpenVPN is an open-source VPN software that creates a secure encrypted tunnel between two systems over a network.

---

### Why use `dev tun`?

* Creates a Layer-3 (IP) tunnel.
* Used for routing IP packets.

---

### Difference between `tun` and `tap`

| TUN         | TAP             |
| ----------- | --------------- |
| Layer 3     | Layer 2         |
| IP Packets  | Ethernet Frames |
| Faster      | Slightly slower |
| Routing VPN | Bridging VPN    |

---

### Why use UDP?

* Lower overhead.
* Faster transmission.
* Better performance for VPN traffic.

---

### Why are `auth none` and `cipher none` used?

Only for **lab/testing purposes** to simplify the setup. In production, authentication and encryption (such as certificates and AES) must always be enabled.

---

### What is `tun0`?

A virtual network interface created by OpenVPN that carries IP traffic through the VPN tunnel.

---

### Why doesn't `tcpdump -i ens33 icmp` show ICMP packets when pinging `10.8.0.1`?

Because the ICMP packet is encapsulated inside a UDP packet on the physical interface. The original ICMP becomes visible only after decapsulation at the `tun0` interface. To observe the encapsulated traffic on the physical interface, you can capture UDP on port 1194:

```bash
sudo tcpdump -i ens33 udp port 1194
```

or capture on the tunnel interface to see the decrypted IP/ICMP traffic:

```bash
sudo tcpdump -i tun0 icmp
```
