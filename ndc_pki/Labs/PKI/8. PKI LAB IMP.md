# PKI LAB EXAM SCENARIO

# Digitally Signing Documents using XCA

---

# Objective

In this lab, you will learn how to create a complete **Public Key Infrastructure (PKI)** hierarchy using **XCA**, consisting of:

* Root CA
* Subordinate CA (Sub CA)
* User Certificate (Tinku)
* Certificate Chain
* Digital Signature on Microsoft Word Document
* Digital Signature on PDF Document

---

# Software Required

* XCA (X Certificate and Key Management)
* Microsoft Word
* Adobe Acrobat Reader / Adobe Acrobat Pro

---

# Folder Structure

Create the following folders before starting.

```text
C:\
└── MyFiles
    └── MyPKI
        ├── Lab1
        │
        ├── 01-RootCA
        ├── 02-SubCA
        └── 03-Tinku
```

---

# Important PKI Terms

| Term              | Meaning                                     |
| ----------------- | ------------------------------------------- |
| PKI               | Public Key Infrastructure                   |
| CA                | Certificate Authority                       |
| Root CA           | Highest trusted authority that signs itself |
| Sub CA            | CA certified by Root CA                     |
| CSR               | Certificate Signing Request                 |
| Private Key       | Secret key used for signing                 |
| Public Key        | Shared key used for verification            |
| Certificate       | Identity + Public Key                       |
| Certificate Chain | Root CA → Sub CA → User Certificate         |
| Digital Signature | Proof of authenticity and integrity         |
| XBD               | XCA Database                                |
| PEM               | Certificate/Private Key format              |
| CRT               | Certificate file                            |
| PFX / PKCS#12     | Certificate + Private Key + Chain           |

---

# Complete PKI Flow

```text
                    ROOT CA
                  (Self Signed)
                        │
             Signs Sub CA Certificate
                        │
                        ▼
                    SUB CA
                        │
          Signs User Certificate (Tinku)
                        │
                        ▼
                 User Certificate
                        │
                        ▼
        Word / PDF Digital Signature
```

# Important Technical Meanings (Short Notes)

| Component         | Purpose                                                                                            |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| Root CA           | Trust anchor; self-signs its own certificate.                                                      |
| Sub CA            | Issues certificates to users after being signed by the Root CA.                                    |
| CSR               | Request containing public key and identity; sent to a CA for signing.                              |
| Private Key       | Used to create digital signatures; never shared.                                                   |
| Public Key        | Used by others to verify signatures.                                                               |
| Certificate       | Binds an identity to a public key.                                                                 |
| Certificate Chain | Links User → Sub CA → Root CA to establish trust.                                                  |
| Digital Signature | Ensures authenticity, integrity, and non-repudiation.                                              |
| PFX (PKCS#12)     | Bundle containing the certificate, private key, and certificate chain for easy import and signing. |

# Exam Viva Questions

**Q1. Why is Root CA self-signed?**
Because there is no higher authority above the Root CA, so it signs its own certificate to establish trust.

**Q2. Why create a Sub CA?**
To keep the Root CA offline and secure while delegating certificate issuance.

**Q3. What is a CSR?**
A Certificate Signing Request that contains the applicant's public key and identity information, which is sent to a CA for signing.

**Q4. Why export a PFX file?**
Because it contains the user's certificate, private key, and certificate chain, allowing applications like Microsoft Word and Adobe Acrobat to perform digital signing.

**Q5. What happens if the document is modified after signing?**
The hash changes, the signature verification fails, and the application reports the document as invalid or tampered with.

**Q6. Why import the Root CA into the Sub CA and User databases?**
To complete the certificate chain so applications can validate the trust path from the user certificate back to the trusted Root CA.
