# Step 1 : Create CA Directory Structure

Move to your home directory.

```bash
cd /home/shuhari
```

Create the required directories.

```bash
mkdir -p ca/{certs,crl,newcerts,private,subca/certs,subca/csr}
```

Verify.

```bash

```

Expected structure

```text
ca/
├── certs
├── crl
├── newcerts
├── private
└── subca
    ├── certs
    └── csr
```

### Purpose of each directory

| Directory   | Purpose                                   |
| ----------- | ----------------------------------------- |
| certs       | Stores issued CA certificates             |
| crl         | Stores Certificate Revocation Lists (CRL) |
| newcerts    | Stores newly issued certificates          |
| private     | Stores private keys                       |
| subca/csr   | Stores SubCA Certificate Signing Requests |
| subca/certs | Stores certificates issued to the SubCA   |

# Step 9 : Generate the Self-Signed Root CA Certificate

Run

```bash
openssl req \
-config rootca.cnf \
-key private/ca.key.pem \
-new \
-x509 \
-days 7300 \
-sha256 \
-extensions v3_ca \
-out certs/ca.cert.pem
```

> **Note:** The correct option is `-extensions` (plural), not `-extension`.

Enter the required details.

Example

```text
State or Province Name: MH

Locality Name: Pune

Organization Name: ShuHaRi Labs

Organizational Unit Name: IS

Common Name: ShuHaRi Root CA

Email Address: info@shuhari.local
```

---

## Explanation

| Option            | Purpose                                  |
| ----------------- | ---------------------------------------- |
| req               | Create a certificate request             |
| -config           | Use the specified OpenSSL configuration  |
| -key              | Sign using the CA private key            |
| -new              | Create a new certificate                 |
| -x509             | Generate a self-signed X.509 certificate |
| -days 7300        | Valid for 20 years                       |
| -sha256           | Use SHA-256 hashing                      |
| -extensions v3_ca | Apply CA-specific certificate extensions |
| -out              | Output certificate file                  |

# Step 11 : Verify the Certificate

Display the certificate in human-readable format.

```bash
openssl x509 -in certs/ca.cert.pem -text -noout
```

### Verify that it is self-signed

Look for these fields:

```text
Issuer:
```

and

```text
Subject:
```

If **Issuer** and **Subject** are identical, the certificate is **self-signed**.

Example

```text
Issuer: CN = ShuHaRi Root CA

Subject: CN = ShuHaRi Root CA
```

This confirms that the Root CA certificate has signed itself, which is the expected behavior for a Root Certificate Authority.

If the browser does not yet trust your CA, import the **Root CA certificate (`ca.cert.pem`)** into the browser's **Trusted Authorities** (or **Authorities**) certificate store.

After importing the Root CA certificate and reopening the site:

* The HTTPS page should load successfully.
* The browser should show **Connection is secure**.
* The certificate chain should appear as:

```text
www.shuhari.local
        │
        ▼
ShuHaRi Sub CA
        │
        ▼
ShuHaRi Root CA
```

This confirms that the server certificate was issued by the **SubCA**, which is trusted because it chains back to the **Root CA**.
