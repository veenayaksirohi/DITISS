# Why Does Cross-Network Ping Fail?

Machine B has two interfaces but **IP forwarding (routing)** is disabled by default. Without routing, packets are not forwarded between VMnet4 and VMnet5.

# If You Want A and D to Communicate

Enable IP forwarding on Machine B.

On Linux:

```bash
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
```

Permanent:

```bash
sudo nano /etc/sysctl.conf
```

Uncomment or add:

```text
net.ipv4.ip_forward=1
```

Apply:

```bash
sudo sysctl -p
```

Now:

```
A
↓
VMnet4
↓
Machine B (Router)
↓
VMnet5
↓
D
```

A and D will be able to ping each other.

This is a standard **two-LAN routing lab**, where **Machine B acts as the router** connecting the two Host-Only networks. Without enabling IP forwarding, communication is limited to devices within the same LAN; after enabling routing, traffic can flow between both LANs.

### VM Adapter Mapping

```
Machine A
└── Adapter A → VMnet4 (Host-Only)

Machine B
├── Adapter B → VMnet4 (Host-Only)
└── Adapter C → VMnet5 (Host-Only)

Machine D
└── Adapter D → VMnet5 (Host-Only)
```

### Why Host-Only?

* **VMnet4** creates an isolated LAN for **A and B**.
* **VMnet5** creates another isolated LAN for **B and D**.
* No Internet access is needed for this routing lab.
* Machine **B** connects both Host-Only networks and can act as a router (if IP forwarding is enabled).

So the answer is **yes—all four adapters are connected to Host-Only networks**. No NAT or Bridged adapters are required for this experiment unless you also want Internet access for package installation.
