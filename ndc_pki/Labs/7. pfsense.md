## 🔰 What is pfSense?

pfSense is a **free, open-source firewall and router** distribution based on **FreeBSD**.
It is installed on physical or virtual hardware and managed entirely through a **Web GUI** (and CLI).
In labs and enterprises it replaces dedicated hardware firewalls like Cisco ASA or Fortinet.

```
                        +------------------------------+
                        |          pfSense             |
  LAN Clients  -------> |  em0 (LAN)   em1 (WAN)  --> |  --> Internet / Other segment
                        |  Firewall  |  NAT  |  DHCP  |
                        |  Routing   |  VPN  |  DNS   |
                        +------------------------------+
```

### Key Facts

| Property       | Value                                       |
| -------------- | ------------------------------------------- |
| Base OS        | FreeBSD                                     |
| Packet Filter  | `pf` (OpenBSD packet filter, ported to BSD) |
| Web GUI        | Accessed via LAN IP on port 443 (HTTPS)     |
| Default LAN IP | 192.168.1.1                                 |
| Default creds  | admin / pfsense                             |
| Shell access   | via console or Diagnostics > Command Prompt |
| License        | Apache 2.0 (Community Edition)              |

## 📦 pfSense Features Overview

### 1. Firewall (pf — Packet Filter)

- Stateful packet inspection (tracks connection state)
- Rules processed **top to bottom**, first match wins
- Rules applied **per interface, per direction** (in/out)
- Supports: IPv4, IPv6, ICMP, TCP, UDP, aliases, schedules

### 2. NAT (Network Address Translation)

```
Type                  Use Case
------------------    -------------------------------------------
Outbound NAT          LAN clients share WAN IP (default enabled)
Port Forward (DNAT)   Expose internal server to WAN
1:1 NAT               Map one public IP to one private IP
NPt (IPv6)            IPv6 prefix translation
```

### 3. Routing

- Static routes (manual)
- Policy-based routing (route by source/dest/port)
- Multi-WAN / load balancing / failover
- Gateway groups

### 4. DHCP Server

- Assign IPs dynamically to LAN clients
- Static leases (MAC → IP binding)

### 5. DNS Resolver (Unbound)

- Built-in recursive DNS resolver
- DNS over TLS support
- Host overrides (custom local DNS entries)

### 6. VPN

| Type      | Use                             |
| --------- | ------------------------------- |
| OpenVPN   | Remote access / site-to-site    |
| IPsec     | Site-to-site enterprise tunnels |
| WireGuard | Fast modern VPN (via package)   |

### 7. Traffic Shaping / QoS

- ALTQ / HFSC queues
- Prioritize VoIP, gaming, etc.

### 8. Packages (Add-ons)

```
Package         Purpose
-----------     ----------------------------------
Snort / Suricata  IDS/IPS
pfBlockerNG     IP/DNS blacklisting (ad block)
Squid           HTTP proxy / caching
Haproxy         Load balancer
Zeek            Network analysis
```

## 🔥 Firewall Rule Processing — Deep Dive

### Rule Evaluation Order

```
Packet arrives on interface
        |
        v
+-------------------+
| Floating Rules    |  (apply to all interfaces, optional)
+-------------------+
        |
        v
+-------------------+
| Interface Rules   |  (LAN rules, WAN rules, etc.)
| (top to bottom)   |
| First match WINS  |
+-------------------+
        |
        v
+-------------------+
| Implicit DENY ALL |  (hidden default — nothing explicit = blocked)
+-------------------+
```

### Rule Fields Explained

| Field       | Description                                       |
| ----------- | ------------------------------------------------- |
| Action      | Pass / Block / Reject                             |
| Interface   | Which NIC the rule applies to                     |
| Direction   | In (arriving) / Out (leaving) — default is **In** |
| Protocol    | TCP / UDP / ICMP / Any                            |
| Source      | IP, subnet, alias, or "any"                       |
| Destination | IP, subnet, alias, or "any"                       |
| Port        | Src port / Dest port (for TCP/UDP)                |
| Log         | Log matching packets to firewall log              |
| State type  | Keep state (stateful) / Synproxy / None           |

### Block vs Reject

```
Block  → silently drops packet (sender gets no response — stealth)
Reject → sends TCP RST or ICMP unreachable back (sender knows it was refused)
```

### Stateful Inspection

```
Connection: Machine A (40.101) ---SYN---> Machine D (50.101)

pfSense creates a STATE ENTRY:
  src: 40.101:xxxx  dst: 50.101:80  proto: TCP  state: SYN_SENT

Return traffic (SYN-ACK from D) is automatically allowed
because it matches an EXISTING state — no explicit rule needed.

Without stateful: you'd need TWO rules (one each direction).
With stateful  : one rule is enough (return traffic is implied).
```

## 🔄 NAT in This Lab Context

In this lab there is **no real internet WAN**, so NAT is not needed for internet access. However, pfSense still applies **outbound NAT** by default:

```
Default Outbound NAT (Automatic mode):
  LAN clients leaving via WAN are NATed to WAN IP (192.168.50.10)

  Machine A (40.101) pings Machine C (50.101):
    Before NAT:  src=192.168.40.101  dst=192.168.50.101
    After NAT:   src=192.168.50.10   dst=192.168.50.101

  Machine C sees ping from 192.168.50.10 (pfSense WAN), NOT from 40.101
```

> **Lab Trap:** If NAT is active and you ping from A to D, the reply goes to pfSense WAN (50.10) — not directly to A. pfSense then forwards it back. If firewall is ON, the return still gets blocked at WAN inbound before NAT de-translation.

To **disable outbound NAT** for pure routing (no masquerading):

```
Firewall > NAT > Outbound
  Mode: Disable Outbound NAT rule generation
```

## 🎯 Interview / Exam Q&A

### Lab-Specific

**Q: Why can A ping B but not D by default?**

> A and B are on the **same subnet** (192.168.40.0/24) — no firewall involved, just L2 switching.
> A and D are on **different subnets** — traffic must route through pfSense which **blocks WAN inbound by default**.

**Q: What is pfSense's default LAN rule?**

> `pass in on em0 all` — allows all traffic from LAN to anywhere (including WAN).

**Q: What is pfSense's default WAN rule?**

> Implicit deny all inbound. Only stateful return traffic is allowed.

**Q: How do you completely disable the pfSense firewall?**

> `pfctl -d` (runtime) or via GUI: System > Advanced > Firewall & NAT > Disable Firewall.

**Q: If firewall is OFF and A still can't ping D, what's the issue?**

> Missing **default gateway** on Machine A or C — packets reach pfSense but replies have no route back.

---

### pfSense Theory

**Q: What OS is pfSense based on?**

> FreeBSD. The packet filter is `pf` (originally from OpenBSD, ported to FreeBSD).

**Q: What is the difference between Block and Reject in pfSense?**

> Block silently drops the packet (attacker gets no feedback — stealth).
> Reject actively sends back a TCP RST or ICMP port unreachable — the sender knows it was denied.

**Q: How does pfSense process firewall rules?**

> Top to bottom, first match wins. There is an implicit deny-all at the bottom that is invisible in the GUI.
> Floating rules are evaluated first, then per-interface rules.

**Q: What is stateful inspection? Does pfSense use it?**

> Yes. pfSense uses `keep state` by default on all pass rules.
> It tracks the full connection (SYN → established → closed) in a state table.
> Return traffic matching an existing state is automatically allowed without a separate rule.

**Q: What is the difference between LAN and WAN interfaces in pfSense?**

> LAN = trusted internal network; default rule is PASS all.
> WAN = untrusted external network; default rule is BLOCK all inbound, PASS stateful returns.

**Q: Can pfSense work as a pure router (no firewall)?**

> Yes — disable pf with `pfctl -d` or toggle off in GUI.
> It then forwards packets between interfaces based purely on the routing table.

**Q: What does "Block private networks" on WAN do?**

> It drops packets sourced from RFC1918 private ranges (10.x, 172.16.x, 192.168.x) arriving on WAN.
> Designed for real internet setups. **Must be unchecked in lab/home environments** where WAN is also a private subnet.

**Q: What is pfTop?**

> A real-time console tool (console option 9) showing active firewall states — like `top` but for pf connections.

**Q: Where do you view blocked/passed packets in real time?**

> Status > Firewall Logs in the GUI, or `clog /var/log/filter.log` in shell.
> Enable logging on specific rules by checking the Log box when creating the rule.

**Q: What is the Diagnostics > States table?**

> Shows all active pf state entries — every tracked connection through pfSense.
> Useful to confirm if a session was established or to manually kill a stuck connection.
