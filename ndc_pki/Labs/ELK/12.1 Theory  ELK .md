# Elasticsearch

**Elasticsearch** is a **distributed, RESTful search and analytics engine** used to store, search, and analyze large amounts of data quickly.

### Features

* Stores data in **JSON** format.
* Provides **fast searching** and **real-time analytics**.
* Can run on a **single machine**.
* Can also run as a **cluster** (multiple machines) for **high availability, scalability, and better performance**.
* Uses **REST APIs** for communication.

---

# Elasticsearch Components

## 1. Index

* An **Index** is a collection of related documents.
* Similar to a **database** in SQL.

**Example**

```
Index: students
```

---

## 2. Document

* A **Document** is the **smallest unit of data** stored in Elasticsearch.
* Stored in **JSON** format.
* Similar to a **row (record)** in a database.

**Example**

```json
{
  "name": "Tinku",
  "PRN": "123",
  "branch": "ENTC"
}
```

---

## 3. Shard

* A **Shard** is a **small part of an index**.
* Elasticsearch divides an index into multiple shards.
* Each shard stores part of the data.
* Improves **search speed** and **performance**.
* Allows data to be distributed across multiple servers.

**Example**

```
Students Index
      |
-------------------------
|        |        |
Shard1  Shard2  Shard3
```

---

## 4. Replica

* A **Replica** is a **copy of a shard**.
* Used for:

  * High Availability
  * Fault Tolerance
  * Faster Search Performance
* If one server fails, the replica continues serving requests.

**Example**

```
Primary Shard 1  ---> Replica Shard 1
Primary Shard 2  ---> Replica Shard 2
```

---

# Cluster

A **Cluster** is a group of one or more Elasticsearch nodes working together.

**Benefits**

* High Availability
* Load Balancing
* Scalability
* Better Performance

---

# Node

A **Node** is a single Elasticsearch server that stores data and participates in the cluster.

Example:

```
Cluster
│
├── Node 1
├── Node 2
└── Node 3
```

---

# Database Comparison

| SQL Database | Elasticsearch       |
| ------------ | ------------------- |
| Database     | Index               |

# Interview / Viva Definition

**Elasticsearch** is a **distributed, RESTful search and analytics engine** that stores data as **JSON documents**. It can run on a **single machine** or as a **cluster**. Data is organized into **indices**, stored as **documents**, divided into **shards**, and protected using **replicas** for high availability and fault tolerance.

# Logstash

**Logstash** is a **real-time, server-side data processing pipeline** that is part of the **ELK Stack** (Elasticsearch, Logstash, Kibana).

It **collects data from different sources, processes (transforms) it, and sends it to one or more destinations**, such as Elasticsearch.

---

# What is ETL?

**ETL** stands for:

* **E – Extract** → Collect data from different sources.
* **T – Transform** → Parse, filter, enrich, and modify the data.
* **L – Load** → Send the processed data to a destination (e.g., Elasticsearch).

---

# Logstash Pipeline

Logstash works using a **Pipeline**.

```text
Input  →  Filter  →  Output
```

---

## 1. Input (Extract)

The **Input** plugin collects data from different sources.

Examples:

* Files
* Databases
* Kafka
* Beats (Filebeat, Metricbeat)
* Syslog
* TCP/UDP
* HTTP

Example:

```text
/var/log/auth.log
        ↓
      Logstash
```

---

## 2. Filter (Transform)

The **Filter** processes and transforms the data.

Common operations:

* Parse logs
* Remove unwanted fields
* Add new fields
* Convert data types
* Extract timestamps
* Enrich data (GeoIP, User Agent)

Common filter plugins:

* grok
* mutate
* date
* json
* geoip

Example:

Before:

```text
Jan 10 Login Success user=harshal
```

After:

```json
{
  "date": "2026-01-10",
  "user": "harshal",
  "status": "Success"
}
```

---

## 3. Output (Load)

The **Output** sends processed data to a destination.

Examples:

* Elasticsearch
* File
* Kafka
* stdout (console)
* Email
* HTTP

Example:

```text
Processed Data
      ↓
Elasticsearch
      ↓
Kibana Dashboard
```

---

# Complete Flow

```text
Log File
    │
    ▼
Input
    │
    ▼
Filter
(Parse, Transform, Enrich)
    │
    ▼
Output
    │
    ▼
Elasticsearch
    │
    ▼
Kibana
```

---

# Why Use Logstash?

* Collects data from multiple sources.
* Processes data in real time.
* Parses and cleans log files.
* Supports hundreds of input, filter, and output plugins.
* Integrates easily with the ELK Stack.

---

# One-Line Definition (Exam)

**Logstash is a real-time, server-side data processing pipeline that performs ETL (Extract, Transform, Load) by collecting data from various sources, processing it, and sending it to destinations such as Elasticsearch.**

---

# Keywords for Viva

* **Logstash** → Data Processing Pipeline
* **ETL** → Extract → Transform → Load
* **Pipeline** → Input → Filter → Output
* **Input** → Reads data
* **Filter** → Processes/Transforms data
* **Output** → Sends data to Elasticsearch or other destinations


# Kibana

**Kibana** is the **visualization and analytics dashboard** of the **ELK Stack** (Elasticsearch, Logstash, Kibana).

It is used to **search, analyze, and visualize data stored in Elasticsearch** through graphs, charts, tables, and dashboards.

---

# Features

* Visualizes data stored in Elasticsearch.
* Creates interactive **Dashboards**.
* Performs **real-time monitoring**.
* Searches and analyzes logs.
* Generates graphs, charts, maps, and reports.
* Helps identify trends, errors, and security events.

---

# How Kibana Works

```text
Data Sources
     │
     ▼
 Logstash / Beats
     │
     ▼
 Elasticsearch
 (Stores Data)
     │
     ▼
    Kibana
(Search, Analyze, Visualize)
```

---
