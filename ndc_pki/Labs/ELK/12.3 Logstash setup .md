# Logstash Pipeline

A Logstash pipeline consists of **three stages**.

```text
Input  →  Filter  →  Output
```

---

# 1. Input (Extract)

The **Input** stage collects data from different sources.

Common Input Plugins

| Plugin | Purpose                                                   |
| ------ | --------------------------------------------------------- |
| beats  | Receives logs from Filebeat, Metricbeat, Winlogbeat, etc. |
| file   | Reads data from log files.                                |
| stdin  | Reads input from the terminal (testing).                  |
| http   | Accepts HTTP requests.                                    |
| syslog | Receives syslog messages.                                 |
| jdbc   | Reads data from databases.                                |
| kafka  | Consumes messages from Kafka.                             |

---

# 2. Filter (Transform)

Processes or modifies incoming data.

Common Filter Plugins

### mutate

Used to modify fields.

Examples:

* uppercase
* lowercase
* add_field
* remove_field
* rename
* convert

Example:

```ruby
mutate {
    uppercase => ["message"]
}
```

---

### grok

Used for **pattern matching (Regular Expressions)** to extract fields from logs.

---

### dns

Performs DNS lookups on IP addresses.

---

# 3. Output (Load)

Sends processed data to a destination.

Common Output Plugins

* Elasticsearch
* stdout
* File
* Syslog
* Nagios
* Kafka

---

# Pipeline File

A Logstash configuration is written inside a **pipeline configuration file (.conf).**

Example:

# Lab 3 : Automatic Pipeline

Instead of running Logstash with

```bash
/usr/share/logstash/bin/logstash -f pipeline.conf
```

copy the configuration to

```text
/etc/logstash/conf.d/
```

Logstash automatically loads every `.conf` file from this directory when started as a service.

Example:

```bash
sudo vi /etc/logstash/conf.d/one.conf
```

# Read APT Installation Logs

APT installation logs are stored in

```text
/var/log/apt/history.log
```

Each installation contains a line beginning with

```text
Commandline:
```

We will capture only those events.

Configuration:

```ruby
input {
    file {
        path => "/var/log/apt/history.log"
        start_position => "end"
        sincedb_path => "/var/lib/logstash/apt.sincedb"
    }
}

filter {
    if [message] =~ /Commandline:/ {
        mutate {
            add_field => {
                "installation_status" => "installed"
            }
        }
    } else {
        drop { }
    }
}

output {
    elasticsearch {
        hosts => ["http://localhost:9200"]
        index => "apt_log"
    }

    stdout {
        codec => rubydebug
    }
}
```

# Start Logstash Service

Reload systemd:

```bash
sudo systemctl daemon-reload
```

Start Logstash:

```bash
sudo systemctl start logstash
```

Enable on boot:

```bash
sudo systemctl enable logstash
```

Check status:

```bash
sudo systemctl status logstash
```

Expected:

```text
active (running)
```

---

# Monitor Logstash Logs

Open a new terminal.

```bash
sudo journalctl -f -n 0 -u logstash
```

Meaning

* `-f` → Follow logs continuously.
* `-n 0` → Show only new log entries.
* `-u logstash` → Display logs for the Logstash service.

---

# Check Sincedb File

Logstash creates a **sincedb** file to remember the last read position.

Verify:

```bash
ls -l /var/lib/logstash/
```

You should see

```text
apt.sincedb
```

---

# Generate New Logs

Install a package in another terminal.

```bash
sudo apt install sl
```

or

```bash
sudo apt install cowsay
```

This writes new entries to

```text
/var/log/apt/history.log
```

Logstash detects the new log and sends it to Elasticsearch.
