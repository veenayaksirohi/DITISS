# Step 2: Install Java

Elasticsearch requires Java.

```bash
sudo apt update
sudo apt install -y default-jdk
```

Verify:

```bash
java -version
```

---

# Step 3: Install curl

Used to communicate with Elasticsearch REST API.

```bash
sudo apt install -y curl
```

---

# Step 4: Install Elasticsearch

Move to the directory containing the package.

```bash
ls -l
```

Install:

```bash
sudo dpkg -i elasticsearch-8.16.1-amd64.deb
```

If dependencies are missing:

```bash
sudo apt --fix-broken install
```

---

## Note

During installation Elasticsearch may display an auto-generated password for the `elastic` user.

Since we are disabling security for this lab, that password is **not required**.

---

# Step 5: Configure Elasticsearch

Open the configuration file.

```bash
sudo vi /etc/elasticsearch/elasticsearch.yml
```

Modify the following:

```yaml
node.name: deb1

cluster.name: my-application

network.host: 0.0.0.0

http.port: 9200

cluster.initial_master_nodes: ["deb1"]

xpack.security.enabled: false

xpack.security.enrollment.enabled: false

xpack.security.transport.ssl:
  enabled: false
```

Save and exit.

---

# Parameter Meaning

### node.name

Unique name of this Elasticsearch node.

Example:

```yaml
node.name: deb1
```

---

### cluster.name

Name of the Elasticsearch cluster.

```yaml
cluster.name: my-application
```

Nodes with the same cluster name join together.

---

### network.host

IP address Elasticsearch listens on.

```yaml
network.host: 0.0.0.0
```

`0.0.0.0` means accept connections from every interface.

---

### http.port

REST API port.

Default:

```yaml
9200
```

---

### cluster.initial_master_nodes

Specifies the first master node during cluster creation.

Example:

```yaml
cluster.initial_master_nodes: ["deb1"]
```

---

### xpack.security.enabled

Disables authentication.

```yaml
false
```

---

### xpack.security.enrollment.enabled

Disables node enrollment.

```yaml
false
```

---

### xpack.security.transport.ssl.enabled

Disables SSL communication between cluster nodes.

```yaml
false
```

# Step 7: Start Elasticsearch



# Step 8: Verify Elasticsearch

Open:

```
http://192.168.129.128:9200
```

or

```bash

```

You should receive a JSON response containing cluster information.

---

# Cluster Health

```bash
curl -X GET "localhost:9200/_cluster/health"
```

Pretty output:

```bash
curl -X GET "localhost:9200/_cluster/health?pretty"
```

## Meaning

* `_cluster` → Cluster information
* `health` → Displays cluster health (green, yellow, red)

> **Note:** This command **does NOT show indexes or documents.**

---

# List All Indexes

```bash
curl -X GET "localhost:9200/_cat/indices?v"
```

or

```bash
curl -X GET "localhost:9200/_alias?pretty"
```

`_cat/indices` is easier to read.

---

# Create an Index

```bash
curl -X PUT "localhost:9200/test1-index1"
```

Verify:

```bash
curl -X GET "localhost:9200/_cat/indices?v"
```

---

# Insert a Document

```bash
curl -X POST "http://localhost:9200/test1-index1/_doc/1?pretty" \
-H "Content-Type: application/json" \
-d '
{
  "name":"Gabbar Singh",
  "age":30,
  "occupation":"Hacker"
}'
```

---

# Retrieve the Document

```bash
curl -X GET "http://localhost:9200/test1-index1/_doc/1?pretty"
```

---

# Verify All Documents

```bash
curl -X GET "localhost:9200/test1-index1/_search?pretty"
```




❌ Wrong command

```

```

✅ Correct

```

```

(`systemctl` is already part of systemd.)

---

❌ Wrong spelling

```
enrollemnet
```

✅ Correct

```
enrollment
```

---

❌ Wrong statement

```
_cluster ==> index
health ==> document
```

✅ Correct

```
_cluster -> Cluster information
health -> Cluster health status
```

---

❌ Wrong statement

```
?pretty=true shows databases
```

✅ Correct

`pretty` only formats JSON output. It does **not** list databases or indexes.

Overall, this sequence is exactly what most ELK practical exams expect. The main corrections were:

* `elasticsearch.yml` (not `elastic.yml`)
* `cluster.initial_master_nodes: ["deb1"]` should be set once (don't uncomment one value and later comment it out unless your instructor specifically asks you to).
* `systemctl` does **not** need to be installed.
* `_cluster/health` checks cluster health, **not** indexes or documents.
* Add `sudo systemctl enable elasticsearch` and `curl http://localhost:9200` as verification steps.
* Add `_search` to verify inserted documents.
