Yes, but there is one important correction before you finalize it.

**Your guide assumes XCA always creates a CSR first for the Sub CA and User.** In reality, **XCA has multiple workflows depending on the version**:

* Some versions let you **Create Signing Request (CSR)** first.
* Other versions **don't have a separate CSR workflow**. Instead, you create the certificate directly and have it signed by the Root CA/Sub CA.

Since your exam uses **XCA**, the safest guide is one that works regardless of the version. Below is the corrected sequence.

---

# PART 2 – Create Root CA

## Step 1 – Create Root CA Database

Open XCA

    ↓

```

```

C:\MyFiles\MyPKI\Lab1\01-RootCA

## Step 2 – Create Root Private Key

```
Private Keys
    ↓
New Key
```

```
Name : RootCA-Key

Algorithm : RSA

Size : 4096
```

Click Create.

---

## Step 3 – Create Root Certificate

```
Certificates

↓

New Certificate
```

Template

```
Root CA
```

Click

```
Apply all
```

### Subject

```
CN = RootCA

O = ABC Pvt Ltd

OU = Security

L = Pune

ST = Maharashtra

C = IN
```

### Source

```
Private Key

↓

RootCA-Key
```

### Extensions

```
CA = TRUE
```

### Key Usage

```
Certificate Sign

CRL Sign
```

### Signing

```
Self Signed
```

Click OK.

---

## Step 4 – Verify

Check

```
Issuer = RootCA

Subject = RootCA
```

Issuer and Subject should be identical.

Right Click

```
RootCA

↓

```

```
X509 Certificate (.crt)
```

Filename

```
01-RootCA.crt
```

**Never export the Root CA private key.**

### Important Note for Your Exam

The only part that **cannot be made universal** is the **Sub CA/User CSR creation**, because it depends on the **XCA version** installed in your lab. Since you already noticed that your version **doesn't have a "Sub CA" template or a direct CSR option**, you should adapt those steps to the options available in your specific XCA interface rather than expecting the exact menus shown in another version.
