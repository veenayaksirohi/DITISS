## PART A — SESSION 15

## 1. What is a Log?

A **log** is a time-stamped record of events and actions generated by software, systems, applications, or devices. Logs provide insight into system operations, security issues, and user behavior — crucial for troubleshooting, performance monitoring, auditing, and detecting security incidents.

### 1.1 Common Log Types

| Log Type | Description |
|---|---|
| **System Logs** | OS-level activities, kernel events, boot logs |
| **Security Logs** | Auth attempts, firewall events, IDS alerts |
| **Application Logs** | Errors, warnings, and activity from apps |
| **Web Server Logs** | HTTP requests, status codes, source IP, user agents |
| **Audit Logs** | Tracks who did what, when, and from where (compliance/forensics) |

---

## 2. Introduction to Log Analyzers

Log analyzers are tools that collect, parse, index, filter, and visualize log data, making it useful for:
- Troubleshooting
- Intrusion detection
- Trend analysis
- Performance monitoring

### 2.1 Common Log Analyzers

| Tool | Notes |
|---|---|

| **Graylog** | Centralized log management |
| **Splunk** | Free and Enterprise versions |

## 3. Introduction to SIEM (Security Information and Event Management)

**SIEM** combines **Security Information Management (SIM)** + **Security Event Management (SEM)** into a centralized platform that provides:
- Log Management
- Event Correlation
- Security Monitoring
- Alerting and Reporting

It helps detect suspicious activity by aggregating and analyzing logs from various sources (firewalls, endpoints, network devices, etc.), normalizing and correlating events in near real time.

### 3.1 Examples of SIEM Solutions

| SIEM | Description |
|---|---|
| **Splunk** | Enterprise-level log analysis and real-time correlation |
| **IBM QRadar** | Threat detection, behavior analysis |
| **ArcSight** | Advanced correlation engine |
| **OSSIM** (AlienVault) | Open-source SIEM |
| **Wazuh + ELK** | Free, scalable SIEM stack |

---

## 4. SIEM Log Forwarding Configuration

To get logs into a SIEM system, log forwarding must be configured across all relevant sources (firewalls, servers, endpoints, cloud services).

### 4.1 Methods
- **Syslog Protocol** (UDP/514 or TCP/514)
- **Agent-based forwarding** (e.g., OSSEC, NXLog, Wazuh agent, Splunk Universal Forwarder)
- **Log shippers** (Logstash, Fluentd, Filebeat/Beats)
- **APIs or Push Connectors**

### 4.2 Configuration Steps
1. Enable and configure logging on the source device (e.g., firewall, server).
2. Define the log forwarding rule (destination IP/port of SIEM).
3. Choose log format (**CEF, LEEF, JSON, raw**).
4. Verify delivery using tools like `tcpdump` or `logger`.

---

## 5. Log Correlation in SIEM

**Log Correlation** is the process of combining related events across multiple systems to identify complex attack patterns that a single log alone can't reveal.

### 5.1 How It Works
- **Correlation Rules** are defined using logical conditions.
- Normalized data is used to create relationships between events.
- **Time windows** help identify sequences of related events.
- Correlation engines also use thresholds and context (asset criticality, user role, threat intel).

### 5.2 Correlation Examples
- Multiple failed logins + privilege escalation + outbound connection → **possible intrusion**.
- Multiple failed logins + successful admin login from a new country → **possible account compromise**.
- Malware detection on endpoint + outbound traffic to known bad IP → **data exfiltration attempt**.

---

## 6. Event Triggering in SIEM

When correlated patterns match certain criteria, **event triggers** fire, leading to:
- Alert generation
- Incident tickets
- Automated responses (**SOAR** integration)
- Dashboard updates

### 6.1 Example Triggers

| Condition | Action |
|---|---|
| 5 failed logins in 60 seconds | Alert |
| File integrity changes + new unknown process | Incident |
| Traffic to blacklisted IP | Block via firewall integration |

> 💡 **Viva Point:** Triggers can integrate with SOAR tools to automate containment — e.g., disabling accounts or blocking IPs automatically.

---

## 7. SIEM Benefits

- Centralized security visibility across firewalls, endpoints, servers, cloud, and applications.
- Real-time (or near-real-time) threat detection via correlation rules.
- Compliance reporting (**PCI-DSS, HIPAA, ISO 27001**, etc.).
- Faster incident response using dashboards, timelines, and integrated playbooks.
- Threat intelligence integration.

## 8. Snort — Overview

**Snort** is an open-source **Network Intrusion Detection System (NIDS)**, developed by Cisco (originally by Martin Roesch). It can operate in **3 modes**:

1. **Sniffer Mode** — Monitors and displays packets in real time.
2. **Packet Logger Mode** — Saves packets to disk for later analysis.
3. **NIDS Mode** — Analyzes traffic using rules to detect threats (generates alerts/logs).

---

## 9. Installing & Testing Snort

### 9.1 Snort on Windows
1. Download Snort for Windows (e.g., from Snort.org).
2. Install **WinPcap/Npcap** to allow packet capture.
3. Configure `snort.conf`:
   - Set paths to rules and logs.
   - Configure network variables (`HOME_NET`, `EXTERNAL_NET`).
4. Run in CMD:
   ```
   snort -c C:\Snort\etc\snort.conf -i 2 -A console
   ```

### 9.2 Snort on Linux
1. Install via package manager:
   ```bash
   sudo apt install snort
   ```
2. Set interface and config in `/etc/snort/snort.conf`.
3. Example run command:
   ```bash
   sudo snort -A console -q -c /etc/snort/snort.conf -i eth0
   ```
4. Test with ICMP (ping):
   ```bash
   ping <some_ip>
   ```
   If a relevant ICMP rule exists, Snort will alert.

## 10. IDS Architecture

A typical IDS architecture has three key layers:

| Layer | Description |
|---|---|
| **Data Collection (Sensors)** | Captures packets from the network |
| **Analysis (Detection Engine)** | Applies rules/patterns/preprocessors to detect threats |
| **Response (Alerting/Logging)** | Generates alerts, logs data |

```
Packets ──▶ [Sensor: Capture] ──▶ [Detection Engine: Rules/Preprocessors] ──▶ [Response: Alert/Log]
```

> 💡 **Viva Point:** Snort fits this architecture by acting as **sensor + analyzer + alert engine** all in one tool.

---

## 11. Bypassing an IDS (Evasion Techniques)

Attackers attempt to evade detection by manipulating traffic so signatures and detection logic fail.

### 11.1 Obfuscation Techniques
- Fragmentation of packets
- Encoding payloads (Unicode, Base64, URL encoding)
- Using uncommon ports
- Altering case in strings

### 11.2 Timing Evasion
- Slow-rate attacks ("Low & Slow")
- Time-distributed scans (spread activity over time to avoid volume-based thresholds)

### 11.3 Payload Obfuscation
- Encrypting payload (SSL/TLS)
- Using polymorphic shellcode

### 11.4 Application-Layer Attacks
- Hiding payloads inside legitimate HTTP/HTTPS requests

> ⚠️ **Exam Trap:** These evasion methods exploit protocol quirks, fragmentation, encoding, timing, and encryption — all designed to hide malicious payloads from signature matching.

---

## 12. Snort Rule Example

```
alert tcp any any -> any 80 (msg:"Possible Web Exploit"; content:"/cmd.exe"; sid:1000001;)
```
This rule detects HTTP traffic containing `/cmd.exe`, which may indicate an attempted Windows command execution via a web-based exploit.

---

## 13. Snort Logs and Alert Types

| Alert Type | Description |
|---|---|
| **Fast alert** | Lightweight, readable alerts |
| **Full alert** | Detailed logs with packet dumps |
| **Unified2** | Binary format for third-party tools (e.g., Snorby, BASE) |

---

## 14. Improving Detection

To minimize bypasses:
- Enable **`frag3`**, **`stream5`**, and other preprocessors in Snort (handle fragmentation and TCP stream reassembly).
- Use **SSL decryption** with proxies to inspect encrypted traffic.
- Correlate Snort logs with other sources via **SIEM integration**.
- Combine **signature-based** detection with **behavioral/anomaly** detection to catch unknown/stealthy threats.
