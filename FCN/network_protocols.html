Core Protocols

Foundational networking protocols spanning transport, application, routing, and network-service layers.

Transport & Network Layer

ProtocolDescriptionPort(s)
TCP Reliable, connection-oriented transport. Ensures ordered delivery and retransmission of lost data. No fixed port
UDP Fast, connectionless transport. No guarantee of delivery or order. No fixed port
IP (IPv4/IPv6) Provides logical addressing and routing between networks. No port
ICMP Used for diagnostics and error reporting (e.g. ping). No port
ARP Maps IPv4 addresses to MAC addresses on a LAN. No port

ProtocolDescriptionPort(s)

Remote Access

ProtocolDescriptionPort(s)
SSH Secure remote login and command execution. TCP 22

Network Services

ProtocolDescriptionPort(s)

Section 02

Secure Protocols

Encrypted and authenticated variants of standard protocols, plus dedicated security tunneling options.

ProtocolDescriptionPort(s)
HTTPS-alt Alternate secure web port for admin panels, dev servers, and reverse proxies. TCP 8443
FTPS FTP over TLS/SSL for secure file transfer. TCP 21 (explicit) TCP 990 (implicit)
SFTP Secure File Transfer Protocol over SSH. Not the same as FTPS. TCP 22
SCP Secure Copy Protocol — copies files between hosts over SSH. Simpler than SFTP. TCP 22
SMTPS Secure SMTP over TLS/SSL. TCP 465
Submission Modern secure email submission using STARTTLS. TCP 587
POP3S Secure POP3 over TLS/SSL. TCP 995
IMAPS Secure IMAP over TLS/SSL. TCP 993
LDAPS LDAP over TLS/SSL for secure directory access. TCP 636
SNMPv3 Secure SNMP with authentication and encryption. UDP 161/162
SSH Secure remote shell, file administration, and tunneling. TCP 22
IPsec VPN tunneling protocol suite for secure IP communication. UDP 500 / 4500
OpenVPN Open-source VPN tunneling protocol. UDP/TCP 1194
WireGuard Modern, high-performance VPN protocol. UDP 51820
✅
Secure Email Ports to Remember

SMTPS: 465  |  Submission (STARTTLS): 587  |  IMAPS: 993  |  POP3S: 995

⚠️
Avoid Telnet in Production

Telnet (port 23) sends all data including credentials in plain text. Always use SSH (port 22) instead.

Section 04

Key Distinctions

Common exam traps and important protocol differences to keep straight.

File Transfer — FTPS vs SFTP vs SCP

FTPS

FTP secured with TLS. Uses ports 21 (explicit) or 990 (implicit). Still based on the FTP protocol.

SFTP

File transfer over SSH. Port 22. A completely separate protocol from FTPS — not FTP at all.

SCP

Secure Copy over SSH. Port 22. Simpler than SFTP — designed purely for copying files, not browsing directories.

💡
Memory Trick

FTPS = FTP + TLS  ·  SFTP = SSH + file transfer  ·  SCP = SSH + copy only. SFTP and SCP share port 22 because both ride over SSH.

SMTP Port Confusion

ℹ️
Port 25 vs 465 vs 587

25 — Server-to-server relay. Not for client submission (often blocked by ISPs). 465 — SMTPS, implicit TLS. 587 — Modern client submission with STARTTLS. Use 587 for your email client.

SNMP vs SNMPv3

⚠️
Always Prefer SNMPv3

Plain SNMP (v1/v2c) sends community strings in clear text. SNMPv3 adds authentication and encryption on the same ports (161/162).

TCP vs UDP — When Each Is Used

TCP (Reliable)

Used when delivery must be guaranteed: HTTP, HTTPS, SSH, FTP, SMTP, POP3, IMAP, BGP, Telnet.

UDP (Fast)

Used when speed matters more than reliability: DNS, DHCP, TFTP, NTP, SNMP, RIP, video/audio streaming.
