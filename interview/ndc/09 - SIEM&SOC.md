# SIEM & SOC — Detailed Notes

## 1. What is SIEM?

**SIEM** stands for **Security Information and Event Management**.

A SIEM collects security logs from many systems, stores them in one place, analyzes them, correlates related events, and generates alerts when suspicious activity is found.

### Simple Definition

> **SIEM is a centralized security platform that collects and analyzes logs from multiple systems to detect suspicious activity and support incident investigation.**

Basic flow:

```text
Firewall Logs
IDS/IPS Logs
Authentication Logs
System Logs
Web Logs
VPN Logs
      ↓
     SIEM
      ↓
Collect + Normalize + Correlate
      ↓
Detect Suspicious Activity
      ↓
Alert
      ↓
SOC Analyst
```

---

# 2. Why is SIEM Needed?

In an organization, security events are generated by many devices.

For example:

```text
Firewall
Server
VPN
Web Server
IDS/IPS
Application
Operating System
```

Each system creates its own logs.

Without SIEM:

```text
Firewall Log → Separate
Linux Log    → Separate
VPN Log      → Separate
IDS Alert    → Separate
Web Log      → Separate
```

A security analyst would need to check each system individually.

With SIEM:

```text
Firewall ─┐
Linux ────┤
VPN ──────┤
IDS ──────┼→ SIEM → Central Analysis
Web ──────┤
Apps ─────┘
```

This makes monitoring and investigation easier.

# 5. Log Aggregation

## What is Log Aggregation?

**Log aggregation** means bringing logs from many different sources into one central location.

# 7. Log Normalization

## What is Log Normalization?

Different systems write logs in different formats.

Example:

Firewall:

```text
SRC=10.0.0.5 DST=192.168.1.10 ACTION=DENY
```

Linux:

```text
Failed password for root from 10.0.0.5
```

VPN:

```text
Login failure source_ip=10.0.0.5 user=admin
```

All of these look different.

SIEM normalization converts them into a common structure.

Example:

```text
Source IP: 10.0.0.5
Destination: 192.168.1.10
Event Type: Authentication Failure
Action: Denied
```

### Simple Definition

> **Normalization converts logs from different formats into a common format so they can be searched and correlated easily.**

---

# 8. Why is Normalization Important?

Without normalization:

```text
Firewall calls it:
SRC_IP

Linux calls it:
remote_host

VPN calls it:
source

Web App calls it:
client_ip
```

The SIEM may have difficulty comparing them.

After normalization:

```text
Source IP
→ Same field for all logs
```

This makes:

- Searching easier
- Correlation easier
- Dashboards easier
- Detection rules more consistent

# 9. What is Correlation?

**Correlation** means connecting multiple related security events to identify a bigger attack pattern.

A single event may not look dangerous.

But several events together may indicate an attack.

Example:

```text
Firewall:
Repeated connection attempts
        +
IDS:
Port scan detected
        +
Linux:
Multiple failed SSH logins
        ↓
SIEM Correlation
        ↓
Possible Reconnaissance / Brute-Force Attack
```

### Simple Definition

> **Correlation combines related events from different systems to identify suspicious patterns that may not be obvious from one log alone.**

The alert may contain:

- Source IP
- Destination IP
- Username
- Timestamp
- Event type
- Severity
- Related logs
- Detection rule name

Example:

```text

Type:
SSH Brute Force

Source:
203.0.113.50

Target:
192.168.1.20

Failed Attempts:
50

Severity:
High
```

---

# 16. Alert vs Event

This is an important distinction.

### Event

Something that happened.

Example:

```text
One failed login
```

### Alert

An event or group of events considered suspicious enough to require attention.

Example:

```text
50 failed logins from same IP
within 2 minutes
```

So:

```text
Event
→ Raw activity

Alert
→ Suspicious activity requiring attention
```

# 19. What are Security Logs?

**Security logs** are records of events generated by systems, applications, and security devices.

Logs help answer questions such as:

- Who connected?
- From where?
- At what time?
- Was access successful?
- What service was used?
- Was traffic blocked?
- Was an attack detected?

# 29. What is SOC?

**SOC** stands for:

### Simple Definition

> **A SOC monitors security alerts and investigates and responds to cyber incidents.**

SIEM

# 34. Step 2 — Triage

**Triage** means quickly checking the alert to determine:

- Is it real?
- How serious is it?
- Which systems are affected?
- Should it be investigated immediately?

### Simple Definition

> Triage is the initial review and prioritization of a security alert.

The analyst checks:

- Alert severity
- Source IP
- Destination
- Username
- Timestamp
- Asset importance
- Similar events

---

# 35. Triage Example

Alert:

```text
10 failed SSH logins
```

Analyst asks:

```text
Is the source IP trusted?
Was this an admin?
Was the login successful later?
Is this a public server?
Are there other related alerts?
```

If activity is expected:

```text
False Positive
```

If suspicious:

```text
Escalate to Investigation
```

# 36. Step 3 — Investigation

**Investigation** means deeply analyzing the incident.

The analyst may check:

- Firewall logs
- Authentication logs
- IDS alerts
- VPN logs
- Endpoint activity
- Web logs
- User activity

Example:

```text
Brute-Force Alert
       ↓
Check Source IP
       ↓
Check Login Failures
       ↓
Check Successful Login
       ↓
Check Commands Executed
       ↓
Check Other Hosts
```

The goal is to understand:

- What happened?
- When?
- How?
- Which systems?
- Which accounts?
- How far did the attacker get?

---

# 37. Step 4 — Containment

**Containment** means stopping the incident from spreading or causing more damage.

Possible actions:

- Block malicious IP
- Isolate compromised host
- Disable user account
- Disconnect system
- Block malicious domain
- Revoke VPN session

Example:

```text
Compromised Server
       ↓
Disconnect from Network
       ↓
Attacker Cannot Spread Further
```

### Simple Definition

> Containment limits the attack and reduces the blast radius.

---

**Eradication** means removing the root cause of the incident.

Actions may include:

- Remove malware
- Delete attacker accounts
- Patch vulnerability
- Change compromised passwords
- Remove malicious files
- Fix misconfiguration
- Close exposed service

Example:

```text
Vulnerability Found
      ↓
Patch Applied
      ↓
Malware Removed
      ↓
Compromised Credentials Reset
```

Actions:

- Restore systems

Flow:

# 54. Time Synchronization and SIEM

Systems should have synchronized time.

Suppose:

```text
Firewall says:
Attack at 10:00

Linux says:
Login at 10:07

IDS says:
Scan at 09:55
```

If system clocks are wrong, correlation becomes difficult.

Therefore organizations commonly use:

> **NTP — Network Time Protocol**

for clock synchronization.

# 69. Interview-Ready Answer — What is SIEM?

> **SIEM stands for Security Information and Event Management. It collects and aggregates logs from systems such as firewalls, IDS/IPS, servers, VPNs, and applications. It normalizes and correlates these events, detects suspicious patterns, generates alerts, provides dashboards, and helps SOC analysts investigate security incidents.**

---

# 70. Interview-Ready Answer — What is Correlation?

> **Correlation means connecting related security events from different sources to identify a larger attack pattern. For example, if a firewall sees repeated connections, an IDS detects a port scan, and Linux records failed SSH logins from the same IP, a SIEM can correlate these events and identify possible reconnaissance followed by brute-force activity.**

---

# 71. Interview-Ready Answer — SIEM vs SOC

> **SIEM is a technology used to collect, normalize, correlate, and analyze security logs. SOC is the security operations team or function that monitors alerts, investigates incidents, and responds to threats. In simple terms, SIEM is a tool used by the SOC.**

---

# 72. Interview-Ready Answer — SOC Workflow

> **A typical SOC workflow starts with an alert. The analyst performs triage to verify and prioritize it, then investigates the event. If a real incident is confirmed, the team contains the threat, eradicates the root cause, recovers the affected systems, and finally documents the incident and lessons learned.**
