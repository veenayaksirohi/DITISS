# Disk and Partition Basics

## sda

* `sda` = First storage device detected by Linux.
* Usually represents the primary HDD or SSD.
* Partitions are represented as:

  * `sda1`
  * `sda2`
  * `sda3`
  * etc.

### Example Layout

```text
sda
├── sda1  → Boot Partition (/boot)
├── sda2  → Root Partition (/)
└── sda3  → Home Partition (/home)
```

### Boot Partition

* Contains files required to start the operating system.
* Stores:

  * Bootloader (GRUB)
  * Linux Kernel
  * Initial RAM Disk (initramfs)

# File System Resizing

## XFS

🔴 Limitation:

* Supports increasing (growing) the file system size.
* Does NOT support decreasing (shrinking) the file system size.

### Commands

Grow:

```bash
xfs_growfs /mountpoint
```

Shrink:

```text
Not Supported
```

### Advantages

🟢 High Performance

🟢 Excellent for large files and large storage systems

🟢 Common in Enterprise Linux distributions

---

## ext4

🟢 Supports both:

* Increasing partition size
* Decreasing partition size

### Commands

Grow:

```bash
resize2fs /dev/sdaX
```

Shrink:

```bash
resize2fs /dev/sdaX SIZE
```

### Advantages

🟢 Flexible resizing

🟢 Reliable journaling

🟢 Widely used in Linux systems

# How File Systems Recover After a Crash

Recovery depends on the file system's journaling mechanism.

---

## ext4 Recovery

### Recovery Method

🟡 Metadata Journaling

Before changes are written to disk:

1. Metadata changes are recorded in the journal.
2. Data is written.
3. Journal entry is marked complete.

### After a Crash

* Journal is replayed.
* Incomplete operations are rolled back.
* File system returns to a consistent state.

### Recovery Tool

```bash
fsck.ext4
```

### Features

🟢 Fast recovery

🟢 Low corruption risk

🟢 Journal replay on boot

---

## XFS Recovery

### Recovery Method

🟡 Metadata Journaling

XFS keeps a transaction log for metadata operations.

### After a Crash

* Log replay occurs automatically during mount.
* Unfinished transactions are completed or discarded.

### Recovery Tool

```bash
xfs_repair
```

### Features

🟢 Very fast recovery

🟢 Excellent scalability

🟢 Efficient for large storage volumes

---

## NTFS Recovery

### Recovery Method

🟡 Transaction Logging

NTFS uses a special journal called:

```text
$LogFile
```

It records metadata changes before committing them.

### After a Crash

* Windows reads the NTFS journal.
* Incomplete transactions are recovered.
* Consistency is restored automatically.

### Recovery Tool

```cmd
chkdsk /f
```

### Features

🟢 Self-healing capabilities

🟢 Metadata protection

🟢 Automatic crash recovery

# Recovery Comparison

| File System | Recovery Mechanism         | Recovery Tool |
| ----------- | -------------------------- | ------------- |
| ext4        | Journal Replay             | fsck.ext4     |
| XFS         | Log Replay                 | xfs_repair    |
| NTFS        | Transaction Log ($LogFile) | chkdsk        |

# Important Viva Questions

### Why is XFS unable to shrink?

Because XFS was designed for high performance and scalability. Its internal structure does not support safe online shrinking.

### Which file system is more flexible for resizing?

✅ ext4

Supports both growing and shrinking.

### What helps a file system recover after a crash?

✅ Journaling / Transaction Logs

These record pending changes before they are committed to disk.

### Which file systems are journaling file systems?

* ext4
* XFS
* NTFS

### Which file system commonly uses fsck?

✅ ext4
