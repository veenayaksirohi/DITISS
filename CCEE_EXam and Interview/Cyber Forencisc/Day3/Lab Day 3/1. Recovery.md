# Cyber Forensics Lab Day 3 – Recovering Data from a Deleted Partition

## Objective

Recover files from a deleted partition using **FTK Imager** and **TestDisk** while following forensic principles of evidence preservation.

---

# Phase 1: Create Evidence in Windows VM

### Step 1: Open Disk Management

1. Login to Windows VM.
2. Press **Win + R**.
3. Type:

```cmd
diskmgmt.msc
```

4. Press Enter.

---

### Step 2: Shrink Existing Partition

1. Right-click the main partition (usually C:).
2. Select **Shrink Volume**.
3. Enter:

```text
2048 MB
```

4. Click **Shrink**.

Result: 2 GB Unallocated Space.

---

### Step 3: Create New Partition

1. Right-click the Unallocated Space.
2. Select **New Simple Volume**.
3. Assign a drive letter.
4. File System:

```text
NTFS
```

5. Finish the wizard.

---

### Step 4: Copy Files into New Partition

Create sample files:

```text
secret.txt
evidence.docx
lab_notes.pdf
```

Copy them into the newly created partition.

You may also create folders and additional files to make recovery more realistic.

Example:

```text
New Volume (D:)
 ├── secret.txt
 ├── evidence.docx
 └── Reports
      └── report.pdf
```

---

# Phase 2: Delete the Partition

### Step 5: Delete Newly Created Partition

1. Open Disk Management.
2. Right-click the new partition.
3. Select:

```text
Delete Volume
```

4. Confirm.

Result:

```text
Partition becomes Unallocated Space
```

The data still exists on disk but the partition entry is removed.

---

# Phase 3: Create a Forensic Image

### Step 6: Create Disk Image Using FTK Imager

On Host Machine:

1. Open FTK Imager.
2. File → Create Disk Image.

Select:

```text
Physical Drive
```

Choose the VM disk.

---

### Step 7: Image Type

Select:

```text
E01
```

(Evidence File Format)

---

### Step 8: Evidence Information

Fill:

```text
Case Number
Examiner Name
Description
```

or leave blank if instructor allows.

---

### Step 9: Save Image

Choose destination.

Example:

```text
D:\Forensics\Day3\
```

Generate:

```text
VM_Image.E01
```

Wait for acquisition to complete.

---

# Phase 4: Mount Image Read-Only

### Step 10: Mount Evidence

In FTK Imager:

```text
File → Image Mounting
```

Select:

```text
VM_Image.E01
```

Enable:

```text
Read Only
```

Click Mount.

---

### Why Read-Only?

Forensic investigations require preservation of evidence.

Read-only mounting ensures:

* No modification of evidence
* Integrity maintained
* Repeatable examination
* Court admissibility

---

# Phase 5: Recover Deleted Partition Using TestDisk

### Step 11: Start TestDisk

On Host Machine:

Right-click:

```text
testdisk_win.exe
```

Select:

```text
Run as Administrator
```

---

### Step 12: Create Log

Select:

```text
Create
```

TestDisk creates a log file.

---

### Step 13: Select Disk

You will see:

```text
Disk /dev/sda
Disk /dev/sdb
```

Identify the mounted image.

Remember:

```text
Physical Disk
Logical Disk
Block Device
Read-Only Device
```

Choose the mounted evidence image.

Press:

```text
Enter
```

---

### Step 14: Partition Table Type

Usually:

```text
EFI GPT
```

Select:

```text
EFI GPT
```

Press Enter.

---

### Step 15: Analyse Disk

Select:

```text
Analyse
```

Press Enter.

---

### Step 16: Quick Search

Select:

```text
Quick Search
```

TestDisk scans for deleted partitions.

You should see:

```text
MS Data
```

representing the deleted NTFS partition.

---

### Step 17: List Files

Highlight recovered partition.

Press:

```text
P
```

Result:

```text
List Files
```

You should see:

```text
secret.txt
evidence.docx
Reports
```

This confirms recoverable content exists.

---

### Step 18: Recover Files

Navigate to desired files.

Press:

```text
Shift + C
```

(Capital C)

Choose recovery destination.

Example:

```text
D:\Recovered\
```

Press Enter.

Files are copied to recovery location.

---

### Step 19: Quit

Press:

```text
Q
```

until TestDisk exits.

---

# Additional Tool

### PhotoRec (QPhotoRec)

If TestDisk cannot restore partition metadata:

Use:

```text
qphotorec_win.exe
```

Purpose:

```text
File Carving
```

Recovers files based on signatures.

Examples:

```text
jpg
png
pdf
docx
xlsx
zip
```

Even if file system metadata is lost.

# Incident Response Portion

## Scenario

"Windows system is compromised"

Collect volatile information first.

---

### Open CMD as Administrator

---

### Date and Time

```cmd
date /t
time /t
```

---

### Hostname

```cmd
hostname
```

---

### Logged-in User

```cmd
whoami
```

---

### System Information

```cmd
systeminfo
```

---

### Active Sessions

```cmd
query user
```

---

### Running Processes

```cmd
tasklist
```

---

### Search CMD/PowerShell Processes

```cmd
tasklist | findstr /i "cmd powershell"
```

---

### Network Connections

```cmd
netstat -ano
```

Look for:

* Suspicious IPs
* Listening Ports
* Established Connections

---

### Open Files

```cmd
openfiles
```

## Lab Outcome

At the end of the lab you should be able to:

1. Create a new partition.
2. Store files in the partition.
3. Delete the partition.
4. Acquire forensic image using FTK Imager.
5. Mount evidence in read-only mode.
6. Use TestDisk to locate deleted partitions.
7. List deleted files.
8. Recover files from deleted partition.
9. Collect basic incident response artifacts from a compromised Windows system.
10. Understand evidence preservation principles in digital forensics.
