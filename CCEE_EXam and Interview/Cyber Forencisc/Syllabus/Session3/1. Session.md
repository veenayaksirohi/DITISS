# Cyber Forensics Notes (Exam-Oriented)

# 1. Evidence Checkout Log

### Definition

An Evidence Checkout Log is a document used to track every movement and handling of digital evidence throughout an investigation.

### Purpose

* Maintains Chain of Custody
* Ensures accountability
* Prevents evidence tampering claims
* Records who accessed evidence and why

### Information Recorded

* Evidence ID
* Description of evidence
* Date and time checked out
* Person receiving evidence
* Purpose of access
* Date and time returned
* Signature of personnel

### Exam Points

* Chain of Custody must never be broken.
* Every transfer of evidence must be documented.
* Missing entries can make evidence inadmissible in court.

### MCQ Points

* Evidence checkout log maintains **chain of custody**.
* Every evidence movement must be **recorded**.
* Unauthorized access can compromise evidence integrity.

# 2. Handling Evidence

### Definition

Handling evidence refers to collecting, preserving, transporting, storing, and analyzing digital evidence without altering it.

### Principles

1. Do not modify original evidence.
2. Create forensic copies.
3. Document every action.
4. Store evidence securely.

### Best Practices

* Use write blockers.
* Wear anti-static protection when required.
* Label evidence properly.
* Maintain chain of custody.

### Types of Evidence

#### Volatile Evidence

Lost after power off.
Examples:

* RAM
* Running processes
* Network connections

#### Non-Volatile Evidence

Remains after shutdown.
Examples:

* Hard disks
* SSDs
* USB drives

### Order of Volatility

1. CPU Registers
2. Cache
3. RAM
4. Network Connections
5. Running Processes
6. Disk Storage
7. Archives/Backups

### Exam Points

* Collect volatile evidence first.
* Never work directly on original evidence.
* Use forensic imaging tools.

### MCQ Points

* RAM is volatile evidence.
* Hard disks are non-volatile evidence.
* Write blockers prevent modifications.

# 3. First Response

### Definition

Actions taken immediately after discovering an incident.

### Objectives

* Protect evidence
* Identify affected systems
* Prevent further damage
* Document observations

### Steps

1. Secure the scene.
2. Identify systems involved.
3. Record system status.
4. Capture volatile data.
5. Preserve evidence.
6. Begin documentation.

### Information to Record

* Date and time
* Logged-in users
* Open applications
* Running processes
* Network connections

### Exam Points

* First responder should not destroy evidence.
* Documentation starts immediately.
* Capture RAM before shutdown.

### MCQ Points

* First responder secures the scene first.
* Memory acquisition should occur before shutdown.
* Documentation begins at incident discovery.

---

# 4. Formulate and Execute Response Strategy

### Definition

Planning and implementing actions to handle the incident.

### Objectives

* Contain incident
* Preserve evidence
* Restore operations
* Minimize damage

### Response Phases

## A. Identification

Determine incident type.

## B. Containment

Prevent spread.

Examples:

* Disconnect infected systems
* Block malicious IPs

## C. Eradication

Remove threat.

Examples:

* Delete malware
* Patch vulnerabilities

## D. Recovery

Restore normal operations.

## E. Lessons Learned

Document findings.

### Exam Points

* Containment occurs before eradication.
* Recovery follows eradication.
* Lessons learned improve future response.

### MCQ Points

* First incident response phase = Identification.
* Malware removal occurs during Eradication.
* Recovery restores business operations.

# 5. Forensic Duplication

### Definition

Creating an exact bit-by-bit copy of digital media.

### Purpose

* Preserve original evidence
* Allow analysis on duplicate copy
* Maintain integrity

### Types

## Logical Copy

Copies files and folders only.

## Physical Copy

Copies entire storage media bit-by-bit.

### Imaging Tools

* FTK Imager
* dd
* EnCase
* Guymager

### Requirements

* Use write blocker
* Generate hash values
* Verify image integrity

### Exam Points

* Analysis is performed on image copy.
* Original evidence remains untouched.
* Physical image captures deleted data.

### MCQ Points

* FTK Imager creates forensic images.
* Bit-stream copy = Forensic duplication.
* Physical imaging includes unallocated space.

# 6. Authenticate the Evidence

### Definition

Verification that evidence has not been modified.

### Hashing

Common Algorithms:

* MD5
* SHA-1
* SHA-256

### Process

1. Calculate original hash.
2. Create forensic image.
3. Calculate image hash.
4. Compare values.

### Integrity Verification

Same Hash = Evidence unchanged

Different Hash = Evidence altered

### Example

Original:

```
SHA256 = ABC123
```

Image:

```
SHA256 = ABC123
```

Result:

```
Evidence Authentic
```

### Exam Points

* Hashing verifies integrity.
* SHA-256 is more secure than MD5.
* Matching hashes prove authenticity.

### MCQ Points

* Hash values verify evidence integrity.
* SHA-256 is commonly used.
* Different hashes indicate modification.

# 7. Investigation

### Definition

Systematic examination of digital evidence to determine facts.

### Phases

## Identification

Locate evidence sources.

## Collection

Acquire evidence.

## Examination

Recover relevant data.

## Analysis

Interpret findings.

## Reporting

Present results.

### Investigation Areas

#### File System Analysis

* Deleted files
* Hidden files
* Metadata

#### Memory Analysis

* Malware
* Processes
* Network connections

#### Network Analysis

* Traffic captures
* Logs
* Intrusions

#### Log Analysis

* Security logs
* Event logs
* Application logs

### Common Tools

* Volatility
* FTK Imager
* Autopsy
* Wireshark
* EnCase

### Exam Points

* Analysis follows examination.
* Reports must be objective.
* Findings should be reproducible.

### MCQ Points

* Volatility is used for memory analysis.
* Wireshark analyzes network traffic.
* Autopsy performs disk forensics.

# 8. Common Mistakes in Cyber Forensics

### Evidence Handling Errors

* Working on original evidence
* Not creating image
* Missing documentation

### Chain of Custody Errors

* Missing signatures
* Incomplete logs
* Unauthorized access

### Technical Errors

* Ignoring volatile data
* Improper shutdown
* No hash verification

### Reporting Errors

* Personal opinions
* Unsupported conclusions
* Missing screenshots

### Exam Points

* Most common mistake: modifying original evidence.
* Missing chain of custody weakens case.
* Lack of documentation affects credibility.

### MCQ Points

* Original evidence should never be analyzed directly.
* Chain of custody is legally important.
* Hash verification must be performed.

# 9. Detection

### Definition

Process of identifying security incidents or suspicious activities.

### Detection Methods

## Signature-Based Detection

Matches known attack patterns.

Examples:

* Antivirus
* IDS signatures

### Advantages

* Fast
* Accurate for known attacks

### Disadvantages

* Cannot detect unknown threats

---

## Anomaly-Based Detection

Detects deviations from normal behavior.

Examples:

* Unusual traffic
* Suspicious logins

### Advantages

* Detects unknown attacks

### Disadvantages

* Higher false positives

---

## Log-Based Detection

Analyzes system and application logs.

Examples:

* Failed logins
* Privilege escalation

---

## Network-Based Detection

Monitors network traffic.

Examples:

* Port scans
* DDoS attacks

---

## Host-Based Detection

Monitors endpoint activities.

Examples:

* File modifications
* Malware execution

### Exam Points

* Signature-based detects known attacks.
* Anomaly-based detects unknown attacks.
* IDS helps identify suspicious activity.

### MCQ Points

* IDS = Intrusion Detection System.
* Signature detection relies on attack signatures.
* Anomaly detection identifies unusual behavior.
