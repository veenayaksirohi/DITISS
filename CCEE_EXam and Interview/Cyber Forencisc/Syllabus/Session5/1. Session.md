# 1. Encoding and Encryption

Many students confuse **Encoding**, **Encryption**, and **Hashing**. These are completely different concepts.

| Feature      | Encoding            | Encryption      | Hashing                |
| ------------ | ------------------- | --------------- | ---------------------- |
| Purpose      | Data representation | Confidentiality | Integrity Verification |
| Reversible   | Yes                 | Yes (with key)  | No                     |
| Key Required | No                  | Yes             | No                     |
| Example      | Base64              | AES, DES, RSA   | MD5, SHA-256           |

---

## Encoding

Encoding converts data into another format for compatibility and transmission.

### Examples

* ASCII
* Unicode
* UTF-8
* Base64

### Example

Text:

```
Hello
```

Base64:

```
SGVsbG8=
```

### Forensic Importance

Investigators often encounter:

* Base64 encoded malware payloads
* Encoded PowerShell commands
* Encoded emails
* Web artifacts

---

## Encryption

Encryption protects confidentiality.

### Types

### Symmetric Encryption

Same key used for:

* Encryption
* Decryption

Examples:

* AES
* DES
* 3DES

### Asymmetric Encryption

Uses:

* Public Key
* Private Key

Examples:

* RSA
* ECC

---

### Forensic Importance

Investigators may encounter:

* Encrypted drives
* BitLocker volumes
* VeraCrypt containers
* Encrypted communications

# 4. Hashing

Hashing converts data into fixed-length digest.

Example:

```
Hello
```

MD5:

```
8b1a9953c4611296a827abf8c47804d7
```

---

## Characteristics

Good hash function should:

### Deterministic

Same input → Same output

### Fast

Quick computation

### Fixed Length

Output length remains same

### Avalanche Effect

Small change → Huge hash change

---

### Example

Input:

```
Hello
```

MD5:

```
8b1a9953...
```

Input:

```
hello
```

MD5:

```
5d41402a...
```

Completely different.

---

## Popular Algorithms

### MD5

128-bit

### SHA-1

160-bit

### SHA-256

256-bit

### SHA-512

512-bit

# 5. Hashing in Digital Forensics (Hashing DLs)

Hashing is critical for evidence integrity.

---

## Why Hash Evidence?

To prove:

> Evidence was not modified.

---

### Procedure

1. Acquire evidence
2. Calculate hash
3. Store evidence
4. Recalculate hash
5. Compare values

If hashes match:

Evidence integrity maintained.

---

* X-Ways

* sha256sum

# 6. MD5 Hash Collisions

## What is Collision?

Two different files generate same hash.

```
File A ≠ File B

MD5(A) = MD5(B)
```

This is called collision.

---

## MD5 Weakness

Researchers successfully created MD5 collisions.

As a result:

❌ MD5 is no longer considered secure for cryptography.

---

### Famous Attack

2008:

Researchers generated rogue CA certificates using MD5 collision techniques.

---

## Forensic Perspective

MD5 is still often used:

* Speed
* Legacy compatibility

But investigators prefer:

* SHA-256
* SHA-512

---

# 7. Hash Collisions

Collision can occur in any hash function.

---

### Ideal Situation

```
Input A → Hash A
Input B → Hash B
```

---

### Collision

```
Input A → XYZ
Input B → XYZ
```

---

## Collision Resistance

A strong hash function should make collisions computationally infeasible.

Examples:

### Strong

* SHA-256
* SHA-512

### Weak

* MD5
* SHA-1

---

## Types

### Accidental Collision

Natural probability.

### Deliberate Collision

Crafted intentionally by attacker.

# 8. Bit Rot

## Definition

Gradual corruption of stored data over time.

Also called:

* Data decay
* Data degradation

---

## Causes

### Storage Media Aging

* HDD
* SSD
* Optical media

### Radiation

Cosmic rays

### Magnetic decay

Hard disks

### Physical damage

Environmental factors

---

## Effects

* Corrupted files
* Missing data
* Backup failure
* Evidence integrity loss

---

## Detection

Using hashes.

Original:

```
SHA256 = ABC123
```

Later:

```
SHA256 = XYZ789
```

Hash mismatch indicates corruption.

---

## Prevention

### Regular Integrity Checks

Hash verification

### Multiple Backups

3-2-1 Rule

### ECC Memory

Error correction

### RAID

Redundancy

### Archival Monitoring

Periodic verification
