# Reverse Proxy using Squid

## Objective

Configure **Squid** as a **Reverse Proxy (Web Accelerator)** to forward client requests to the backend web server.

### Lab Machines

| Machine        | IP Address          | Purpose                           |
| -------------- | ------------------- | --------------------------------- |
| **Deb1**       | **192.168.229.141** | Squid Reverse Proxy               |
| **Deb2**       | **192.168.229.100** | Backend Web Server (Apache/Nginx) |
| **Squid Port** | **3128**            | Reverse Proxy Listening Port      |

---

# 1. Install Squid (Deb1)

```bash
sudo apt update
sudo apt install squid -y
```

---

# 2. Edit Squid Configuration

```bash
sudo vi /etc/squid/squid.conf
```

The important sections are:

* ACL
* http_access
* http_port
* cache_peer

---

# 3. Create ACL

Under the ACL section, add:

```conf
acl my_site_acl dst 192.168.229.100
```

### Explanation

* `my_site_acl` → ACL Name
* `dst` → Destination IP
* `192.168.229.100` → Backend Web Server (Deb2)

---

# 4. Allow HTTP Access

Under the `http_access` section add:

```conf
http_access allow all
```

Place this **before**

```conf
http_access deny all
```

---

# 5. Configure Squid as Reverse Proxy

Under the `http_port` section add:

```conf
http_port 3128 accel vhost defaultsite=192.168.229.100
```

### Explanation

| Parameter                     | Meaning                                  |
| ----------------------------- | ---------------------------------------- |
| `3128`                        | Squid listens on port 3128               |
| `accel`                       | Enables Reverse Proxy (Accelerator Mode) |
| `vhost`                       | Supports Virtual Hosting                 |
| `defaultsite=192.168.229.100` | Default backend web server               |

---

# 6. Configure Backend Server

Under the `cache_peer` section add:

```conf
cache_peer 192.168.229.100 parent 80 0 no-query originserver name=myserver
```

### Explanation

| Parameter         | Meaning                            |
| ----------------- | ---------------------------------- |
| `192.168.229.100` | Backend Apache/Nginx Server (Deb2) |
| `parent`          | Parent server                      |
| `80`              | HTTP Port                          |
| `0`               | ICP Port Disabled                  |
| `no-query`        | Do not send ICP queries            |
| `originserver`    | Backend is the original web server |
| `name=myserver`   | Backend server name                |

---

# 7. Allow Requests to Backend

Immediately below the `cache_peer` entry add:

```conf
cache_peer_access myserver allow my_site_acl
cache_peer_access myserver deny all
```

---

# 8. Check Configuration

```bash
sudo squid -k parse
```

If no errors are displayed, continue.

---

# 9. Restart Squid

```bash
sudo systemctl restart squid
```

Check status:

```bash
sudo systemctl status squid
```

---

# 10. Test Reverse Proxy

From any client machine, open:

```text
http://192.168.229.141:3128
```

or

```bash
curl http://192.168.229.141:3128
```

You should receive the webpage hosted on the backend server (**192.168.229.100**).

---

# Final Squid Configuration

```conf
####################################
# Reverse Proxy Configuration
####################################

acl my_site_acl dst 192.168.229.100

http_access allow all

http_port 3128 accel vhost defaultsite=192.168.229.100

cache_peer 192.168.229.100 parent 80 0 no-query originserver name=myserver

cache_peer_access myserver allow my_site_acl
cache_peer_access myserver deny all
```

   ├──────────────► Yes

# Role of Each Configuration Directive

| Configuration                                                                | Purpose                                                      |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `http_port 3128 accel`                                                       | Enables Reverse Proxy mode.                                  |
| `defaultsite=192.168.229.100`                                                | Sets the default backend web server.                         |
| `acl my_site_acl dst 192.168.229.100`                                        | Defines an ACL matching the backend destination.             |
| `http_access allow all`                                                      | Allows clients to access Squid.                              |
| `cache_peer 192.168.229.100 parent 80 0 no-query originserver name=myserver` | Defines the backend server that receives forwarded requests. |
| `cache_peer_access myserver allow my_site_acl`                               | Allows requests matching the ACL to use the backend server.  |
| `cache_peer_access myserver deny all`                                        | Denies all other requests to that backend.                   |

---

# Advantages of Reverse Proxy

* Hides the backend server's IP from clients.
* Improves performance through caching.
* Reduces load on the backend server.
* Can distribute requests to multiple backend servers (load balancing).
* Adds a security layer by exposing only the proxy to clients.
* Centralizes logging and access control.

## In your lab

* **Deb1 (192.168.229.141)** runs **Squid** on port **3128**.
* **Deb2 (192.168.229.100)** runs **Apache/Nginx** on port **80**.
* Clients send requests only to **192.168.229.141:3128**.
* Squid forwards the requests to **192.168.229.100**, receives the response, optionally caches it, and returns it to the client.
