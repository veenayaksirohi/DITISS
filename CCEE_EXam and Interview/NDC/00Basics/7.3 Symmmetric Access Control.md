# Modern Cryptography – Symmetric Key Cryptography (Secret Key Cryptography)

## Definition

**Symmetric Key Cryptography** is an encryption technique in which the **sender and receiver use the same secret key** (or identical copies of the same key) for both encryption and decryption.

* **Encryption:** Plaintext → Ciphertext
* **Decryption:** Ciphertext → Plaintext
* Both parties **must know the same secret key** before communication begins.

### Working

```text
            Secret Key (K)
                 │
                 ▼
Sender                     Receiver
-------                    --------
Plaintext                  Ciphertext
    │                          │
Encrypt using K          Decrypt using K
    │                          │
Ciphertext  ───────────►   Plaintext
```

---

# Example

Suppose:

* Plaintext = **HELLO**
* Secret Key = **K123**

Sender encrypts:

```text
HELLO + K123 → X7A91P
```

Receiver decrypts:

```text
X7A91P + K123 → HELLO
```

Only someone having **K123** can read the message.

# Advantages

### 1. Very Fast

* Encryption and decryption are much faster than asymmetric encryption.
* Suitable for encrypting large files and real-time communication.

**Example**

* VPN
* Disk encryption
* Wi-Fi (WPA2/WPA3)

---

### 2. Less Computational Power

Requires:

* Less CPU
* Less Memory
* Less Time

Suitable for:

* Mobile devices
* IoT devices

---

### 3. Efficient for Large Data

Encrypting a 5 GB file is much faster with symmetric algorithms than asymmetric algorithms.

---

### 4. Simple Algorithm

Uses mathematical substitution, permutation, XOR operations, etc.

# Disadvantages

## 1. Key Distribution Problem (First-Time Key Sharing)

Before communication starts, both users **must already share the secret key**.

The biggest challenge is:

> **How do the sender and receiver securely exchange the secret key?**

If the key is sent over an insecure network, an attacker can steal it.

Example:

```text
Alice -----Internet----- Bob

Need to share Secret Key

If attacker captures the key,
all future messages can be decrypted.
```

This is called the **Key Distribution Problem**.

---

## 2. Scalability Problem

As the number of users increases, the number of keys grows rapidly.

Formula:

If **N** users want secure communication with every other user,

[
\boxed{\frac{N(N-1)}{2}}
]

or

```text
N(N-1)
-------
   2
```

### Example

| Users (N) | Keys Required |
| --------- | ------------- |
| 2         | 1             |
| 3         | 3             |
| 4         | 6             |
| 5         | 10            |
| 10        | 45            |
| 100       | 4950          |

Example with 4 users:

```text
A B C D

A-B
A-C
A-D
B-C
B-D
C-D

Total = 6 keys
```

As the number of users increases, managing thousands of secret keys becomes difficult.

This is called the **Scalability Problem** or **Key Management Problem**.

---

## 3. Key Management Problem

The organization must:

* Generate keys
* Store keys
* Protect keys
* Rotate keys
* Revoke old keys

Managing many secret keys becomes difficult.

---

## 4. No Authentication

Authentication means:

> **How can the receiver prove who actually sent the message?**

Suppose:

Alice and Bob share the same secret key.

Bob receives:

```text
Encrypted Message
```

Bob only knows:

> Someone who has the secret key encrypted it.

He **cannot prove whether it was Alice or someone else who also knows the key**.

Therefore,

**Authentication is not provided by basic symmetric encryption.**

---

## 5. No Non-Repudiation

**Non-Repudiation** means:

> The sender cannot deny sending the message later.

Example:

Alice and Bob share the same key.

Later Alice says:

> "I never sent that message."

Can Bob prove she sent it?

**No.**

Why?

Because **both Alice and Bob know the same secret key**. Either one could have created the encrypted message.

So there is **no proof of origin**.

Hence:

**Symmetric encryption does not provide non-repudiation.**

---

## Why Authentication and Non-Repudiation Are Not Available?

Suppose:

```text
Alice  <------ Secret Key K ------> Bob
```

Both know **K**.

Encrypted message:

```text
Encrypt(Message, K)
```

Bob knows:

✔ Someone with key **K** encrypted it.

But he **cannot identify which person** because both possess the same key.

Therefore:

* Cannot verify the actual sender (**No Authentication**)
* Sender can deny sending it (**No Non-Repudiation**)

# Most Important Algorithms for Exams

### DES

* Developed in 1977
* 56-bit key
* 64-bit block
* Now insecure due to brute-force attacks.

---

### 3DES

* DES applied **three times**
* More secure than DES
* Much slower
* Being phased out.

---

### Blowfish

* Designed by Bruce Schneier
* Free and fast
* Variable key length
* 64-bit block size.

---

### Twofish

* Improved version of Blowfish
* 128-bit block
* Supports keys up to 256 bits
* Very secure.

---

### IDEA

* 128-bit key
* Used in older versions of PGP
* Combines addition, multiplication, and XOR operations.

---

### RC4

* Stream cipher
* Very fast
* Previously used in SSL/TLS and WEP
* Now insecure due to known attacks.

---

### RC5

* Parameterized algorithm
* Variable key length
* Variable block size
* Variable number of rounds.

---

### RC6

* Improved RC5
* 128-bit block
* AES finalist
* Good performance but not selected as AES.

---

### AES (Most Important)

* Replaced DES.
* Current encryption standard.
* Block size: **128 bits**
* Key sizes:

  * 128 bits
  * 192 bits
  * 256 bits
* Fast, secure, and widely used.

**Applications:**

* HTTPS/TLS
* Wi-Fi (WPA2/WPA3)
* VPNs
* Disk encryption (e.g., BitLocker, FileVault)
* Cloud storage
* Banking systems

# Is There Key Exchange in Symmetric Cryptography?

**Answer:**

* **Symmetric encryption itself does not include a key exchange mechanism.**
* It **assumes both parties already share the same secret key** before encryption starts.

In practice, the secret key is established using a secure method, such as:

* **Physical exchange** (e.g., handing over a USB drive)
* **Pre-shared key (PSK)** configured in advance
* **Asymmetric cryptography** (e.g., using the Diffie–Hellman key exchange or Elliptic-curve Diffie–Hellman protocol to agree on a shared secret)

After the shared secret is established, a symmetric algorithm like **AES** is used for the actual data encryption because it is much faster.

Yes. **Symmetric-key algorithms are primarily used for encryption and decryption of data**, but they can also be used for a few other security functions. The important distinction is:



* **Symmetric encryption algorithms (AES, DES, Blowfish, etc.)** → Encrypt and decrypt data.

* **Symmetric cryptography as a whole** → Includes encryption and also message authentication techniques such as MAC/HMAC.



## 1. Symmetric Encryption (Main Use)



Uses the **same secret key** to:



* Encrypt plaintext → Ciphertext

* Decrypt ciphertext → Plaintext



Example:



```text

Plaintext --AES + Secret Key--> Ciphertext

Ciphertext --AES + Same Secret Key--> Plaintext

```



Algorithms:



* AES

* DES

* 3DES

* Blowfish

* Twofish

* IDEA

* RC5

* RC6



---



## 2. Is Symmetric Key Exchange Used?



**No.**



This is a common confusion.



A **symmetric algorithm does not perform key exchange**.



It **assumes the secret key is already shared** between the sender and receiver.



```text

Step 1: Share Secret Key (using another method)

Step 2: Use AES/DES to encrypt data

```



So:



* ❌ AES does not exchange keys.

* ❌ DES does not exchange keys.

* ❌ Blowfish does not exchange keys.



---



## 3. Then How Is the Secret Key Shared?



Using one of these methods:



* Physical exchange (USB, paper, face-to-face)

* Pre-Shared Key (PSK)

* Asymmetric key exchange (most common on the Internet), such as Diffie–Hellman key exchange or Elliptic-curve Diffie–Hellman



After both parties obtain the same secret key:



```text

Shared Secret Key

        │

        ▼

     AES Encryption

```



---



## 4. Other Uses of Symmetric Keys



Besides encryption, symmetric keys are also used for:



* **Message Authentication Codes (MAC)** – Verify message authenticity.

* **HMAC (Hash-based Message Authentication Code)** – Verify message integrity and authenticity.



Example:



```text

Message + Secret Key

        │

       HMAC

        │

Authentication Code

```



HMAC **does not encrypt data**; it proves that the message was created by someone who knows the secret key and that it was not modified.

## Exam Answer (2 Marks)



**Is symmetric key exchange used only for encryption?**



**Answer:**



* Symmetric-key algorithms are mainly used for **encryption and decryption** using the same secret key.

* They **do not perform key exchange**; the secret key must be shared beforehand using another secure method (such as a pre-shared key or an asymmetric key exchange protocol).

* Symmetric keys can also be used for **message authentication** (e.g., MAC/HMAC), not just encryption.
