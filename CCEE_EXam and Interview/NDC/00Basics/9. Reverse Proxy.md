# Nginx Reverse Proxy Setup

### Scenario

| Server   | Role                | IP             |
| -------- | ------------------- | -------------- |
| Debian 1 | Apache Backend      | 192.168.80.130 |
| Debian 2 | Nginx Reverse Proxy | 192.168.80.131 |

Client → Nginx (Deb2) → Apache (Deb1)

---

## Step 1: Verify Apache Backend

On **Debian 1 (Apache Server)**

```bash
sudo apt update
sudo apt install apache2 -y
```

Check service:

```bash
sudo systemctl status apache2
```

Create test page:

```bash
echo "<h1>Apache Backend Server</h1>" | sudo tee /var/www/html/index.html
```

Test from Nginx machine:

```bash
curl http://192.168.80.130
```

Expected:

```html
<h1>Apache Backend Server</h1>
```

---

# Step 2: Install Nginx

On **Debian 2 (Reverse Proxy)**

```bash
sudo apt update
sudo apt install nginx -y
```

Check:

```bash
sudo systemctl status nginx
```

Enable at boot:

```bash
sudo systemctl enable nginx
```

---

# Step 3: Remove Default Configuration

Remove default virtual host:

```bash
sudo rm /etc/nginx/sites-enabled/default
sudo rm /etc/nginx/sites-available/default
```

Verify:

```bash
tree /etc/nginx/sites-*
```

Output:

```text
/etc/nginx/sites-available
/etc/nginx/sites-enabled
```

---

# Step 4: Create Reverse Proxy Configuration

Create file:

```bash
sudo vi /etc/nginx/sites-available/rp.conf
```

Add:

```nginx
server {

    listen 80;

    server_name _;

    location / {

        proxy_pass http://192.168.80.130;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

    }

}
```

### Explanation

| Directive        | Purpose                     |
| ---------------- | --------------------------- |
| listen 80        | Listen on HTTP port         |
| proxy_pass       | Forward requests to Apache  |
| proxy_set_header | Preserve client information |

---

# Step 5: Enable Site

Create symbolic link:

```bash
sudo ln -s /etc/nginx/sites-available/rp.conf /etc/nginx/sites-enabled/
```

Verify:

```bash
ls -l /etc/nginx/sites-enabled/
```

Expected:

```text
rp.conf -> /etc/nginx/sites-available/rp.conf
```

---

# Step 6: Test Configuration

```bash
sudo nginx -t
```

Expected:

```text
syntax is ok
test is successful
```

---

# Step 7: Restart Nginx

```bash
sudo systemctl restart nginx
```

Verify:

```bash
sudo systemctl status nginx
```

---

# Step 8: Firewall (If Required)

Allow HTTP:

```bash
sudo ufw allow 80/tcp
sudo ufw reload
```

or

```bash
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
```

---

# Step 9: Testing

From client machine:

```bash
http://192.168.80.131
```

or

```bash
curl http://192.168.80.131
```

Expected output:

```html
<h1>Apache Backend Server</h1>
```

Even though the content is coming from Apache (192.168.80.130), users only see the Nginx server (192.168.80.131).

```text
     v

+----------------+
```

# Useful Commands

```bash
sudo nginx -t                    # Check config
sudo systemctl restart nginx     # Restart
sudo systemctl reload nginx      # Reload
sudo systemctl status nginx      # Status

curl http://192.168.80.130       # Test backend
curl http://192.168.80.131       # Test reverse proxy
```

### Troubleshooting

```bash
sudo tail -f /var/log/nginx/error.log
sudo tail -f /var/log/nginx/access.log
```

Check connectivity to backend:

```bash
ping 192.168.80.130
curl http://192.168.80.130
```

If `curl` to backend fails, Nginx reverse proxy will also fail.
