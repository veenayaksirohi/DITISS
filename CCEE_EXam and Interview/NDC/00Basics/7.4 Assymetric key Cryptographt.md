# Asymmetric Key Cryptography (Public Key Cryptography)

## Definition

Asymmetric cryptography is an encryption technique that uses **two different keys**:

* **Public Key** → Shared openly with everyone.
* **Private Key** → Kept secret by the owner.

A message encrypted with one key can only be decrypted with the other key.

---

## Keys Used

| Key         | Purpose                                 | Shared? |
| ----------- | --------------------------------------- | ------- |
| Public Key  | Encrypt data / Verify digital signature | Yes     |
| Private Key | Decrypt data / Create digital signature | No      |

---

## Secure Message Format (Confidential Communication)

When **A wants to send a secure message to B**:

```
Sender (A)                     Receiver (B)

Plaintext
    │
    ▼
Encrypt using B's Public Key
    │
    ▼
Ciphertext ---------------------> Ciphertext
                                     │
                                     ▼
                           Decrypt using B's Private Key
                                     │
                                     ▼
                                Plaintext
```

### Steps

1. B shares **Public Key**.
2. A encrypts the message using **B's Public Key**.
3. Ciphertext is sent over the network.
4. Only B can decrypt it using **B's Private Key**.

✔ Ensures **Confidentiality**.
✅ Confidentiality
❌ Authentication
❌ Integrity
❌ Non-repudiation

Why not authenticity?

Anyone who knows B's public key can encrypt a message and send it to B. Since the public key is publicly available, B cannot be sure who actually sent the message.

---

## Open Message Format (Authentication / Digital Signature)

When **A wants to prove the message came from A**:

```
Sender (A)                     Receiver (B)

Plaintext
    │
    ▼
Encrypt (Sign) using A's Private Key
    │
    ▼
Signed Message -----------------> Signed Message
                                      │
                                      ▼
                          Verify using A's Public Key
                                      │
                                      ▼
                              Original Message
```

### Steps

1. A signs the message using **A's Private Key**.
2. Anyone with A's **Public Key** can verify it.
3. Confirms the sender is A.

✔ Ensures:

* Authentication
* Integrity
* Non-repudiation

---

# Summary

| Purpose               | Encryption Key        | Decryption / Verification Key | Security Property                          |
| --------------------- | --------------------- | ----------------------------- | ------------------------------------------ |
| Secure Message        | Receiver's Public Key | Receiver's Private Key        | Confidentiality                            |
| Open (Signed) Message | Sender's Private Key  | Sender's Public Key           | Authentication, Integrity, Non-repudiation |

---

## Easy Exam Trick

### Secure Message

> **Public Key → Encrypt**
> **Private Key → Decrypt**

### Open (Signed) Message

> **Private Key → Sign**
> **Public Key → Verify**

This is the basic concept of **asymmetric (public-key) cryptography** and the difference between **secure message** and **open (digitally signed) message** formats.  



---

## Advantages

| Advantage                       | Explanation                                                         |
| ------------------------------- | ------------------------------------------------------------------- |
| **Secure Key Distribution**     | Public key can be shared openly; private key remains secret.        |
| **Authentication**              | Confirms the identity of the sender using digital signatures.       |
| **Confidentiality**             | Only the private key owner can decrypt the message.                 |
| **Non-Repudiation**             | Sender cannot deny sending a digitally signed message.              |
| **Supports Digital Signatures** | Ensures message authenticity and integrity.                         |
| **No Shared Secret Needed**     | Eliminates the need to exchange a secret encryption key beforehand. |

---

## Disadvantages

| Disadvantage                    | Explanation                                                                        |
| ------------------------------- | ---------------------------------------------------------------------------------- |
| **Slower**                      | Encryption and decryption are much slower than symmetric cryptography.             |
| **High Computational Cost**     | Requires more CPU power and memory.                                                |
| **Large Key Size**              | Needs larger keys (e.g., RSA 2048-bit) for strong security.                        |
| **Not Suitable for Large Data** | Encrypting large files is inefficient.                                             |
| **Complex Key Management**      | Public Key Infrastructure (PKI) and certificates are needed to verify public keys. |

---

## Examples

| Algorithm                         | Purpose                                                 |
| --------------------------------- | ------------------------------------------------------- |
| RSA                               | Encryption, Digital Signatures                          |
| Diffie–Hellman key exchange       | Secure Key Exchange                                     |
| Elliptic Curve Cryptography       | Encryption, Digital Signatures (used in modern systems) |
| Digital Signature Algorithm (DSA) | Digital Signatures only                                 |
| ElGamal encryption                | Encryption and Digital Signatures                       |

---

## Real-Life Applications

* **HTTPS (SSL/TLS)** – Secure web browsing.
* **SSH** – Secure remote login.
* **PGP/GPG** – Secure email encryption.
* **Digital Certificates** – Website and user authentication.
* **Cryptocurrencies** – Wallet addresses and transaction signing.

# MAC and CMAC 

# 1. Message Authentication Code (MAC)

## Definition

A **Message Authentication Code (MAC)** is a cryptographic value generated using a **secret key** and a **message** to verify:

* **Message Integrity** (message is not modified)
* **Message Authentication** (message is from the correct sender)

> **MAC does not provide confidentiality** because it does not encrypt the message.

---

## Working

```
Sender
-------
Message + Secret Key
        │
   MAC Algorithm
        │
      MAC Tag
        │
Send → Message + MAC

Receiver
---------
Message + Secret Key
        │
   MAC Algorithm
        │
Generate New MAC
        │
Compare MACs
        │
Match → Accept
Not Match → Reject
```

---

## Advantages

* Ensures message integrity.
* Authenticates the sender.
* Fast and efficient.
* Easy to implement.

---

## Disadvantages

* Does not provide confidentiality.
* Requires sender and receiver to share the same secret key.
* Does not provide non-repudiation.

---

## Applications

* Secure network communication
* Banking transactions
* APIs
* VPNs

---

# 2. HMAC (Hash-based Message Authentication Code)

## Definition

**HMAC** is a type of MAC that uses a **cryptographic hash function** (such as SHA-256 or SHA-512) together with a secret key.

**Formula**

```
HMAC = Hash(Secret Key + Message)
```

---

## Working

```
Message
   +
Secret Key
      │
 Hash Function
(SHA-256/SHA-512)
      │
   HMAC Value
```

---

## Advantages

* Very secure.
* Fast computation.
* Detects message modification.
* Works with existing hash algorithms.
* Resistant to many cryptographic attacks.

---

## Disadvantages

* Requires a shared secret key.
* Does not encrypt data.
* No non-repudiation.

---

## Examples

* HMAC-SHA256
* HMAC-SHA1
* HMAC-SHA512

---

## Applications

* HTTPS
* API Authentication
* OAuth Tokens
* JWT Authentication
* VPN Authentication

---

# 3. CMAC (Cipher-based Message Authentication Code)

## Definition

**CMAC** is a MAC algorithm that uses a **block cipher** (such as AES) instead of a hash function to authenticate a message.

Unlike HMAC, CMAC uses encryption algorithms.

---

## Working

```
Message
   +
Secret Key
      │
AES Block Cipher
      │
   CMAC Value
```

---

## Advantages

* Highly secure.
* Uses AES encryption.
* Provides message integrity and authentication.
* Efficient for hardware implementation.

---

## Disadvantages

* Requires a shared secret key.
* Slower than HMAC in software.
* Does not provide confidentiality.
* No non-repudiation.

---

## Examples

* AES-CMAC
* 3DES-CMAC

---

## Applications

* Smart Cards
* Embedded Systems
* IoT Devices
* Wireless Security
* Government and Military Systems

---

# Difference Between MAC, HMAC and CMAC

| Feature                  | MAC                         | HMAC                                   | CMAC                                     |
| ------------------------ | --------------------------- | -------------------------------------- | ---------------------------------------- |
| Full Form                | Message Authentication Code | Hash-based Message Authentication Code | Cipher-based Message Authentication Code |
| Based On                 | General concept             | Hash Function                          | Block Cipher                             |
| Uses                     | Secret Key                  | Secret Key + Hash                      | Secret Key + AES/Block Cipher            |
| Algorithm                | Any MAC algorithm           | SHA-256, SHA-512, etc.                 | AES, 3DES                                |
| Provides Integrity       | ✅                           | ✅                                      | ✅                                        |
| Provides Authentication  | ✅                           | ✅                                      | ✅                                        |
| Provides Confidentiality | ❌                           | ❌                                      | ❌                                        |
| Speed                    | Depends on algorithm        | Faster in software                     | Faster in hardware                       |
| Example                  | Generic MAC                 | HMAC-SHA256                            | AES-CMAC                                 |

---

# Exam Points (5 Marks)

### Message Authentication Code (MAC)

* Verifies message integrity and sender authentication.
* Uses a shared secret key.
* Does not encrypt the message.
* Does not provide non-repudiation.

### HMAC

* Uses a hash function (SHA-256, SHA-512) and a secret key.
* Fast and highly secure.
* Used in HTTPS, APIs, JWTs, and VPNs.

### CMAC

* Uses a block cipher (AES or 3DES) and a secret key.
* Suitable for hardware, smart cards, and embedded systems.
* Provides integrity and authentication but not confidentiality.
