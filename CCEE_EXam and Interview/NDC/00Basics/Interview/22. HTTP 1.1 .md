# HTTP/1.1

## Definition

**HTTP/1.1 ** is an **application-layer protocol** used for communication between a **web client (browser)** and a **web server**. It defines how requests and responses are formatted and transmitted over the Internet.

* **Protocol:** Application Layer
* **Transport Protocol:** TCP
* **Default Port:** 80 (HTTP), 

---

## Features of HTTP/1.1

| Feature                   | Description                                                                     |
| ------------------------- | ------------------------------------------------------------------------------- |
| Persistent Connections    | Keeps the TCP connection open for multiple requests (Keep-Alive).               |
| Host Header               | Allows multiple websites to share one IP address (Virtual Hosting).             |
| Chunked Transfer Encoding | Sends data in chunks when total size is unknown.                                |
| Cache Control             | Supports browser and proxy caching.                                             |
| Pipelining                | Multiple requests can be sent without waiting (rarely used due to limitations). |
| Request Methods           | GET, POST, PUT, DELETE, HEAD, OPTIONS, PATCH, etc.                              |

---

## Working of HTTP/1.1

```text
Client (Browser)
       |
       | HTTP Request
       v
Web Server
       |
       | HTTP Response
       v
Client displays webpage
```

---

## HTTP Request Format

```http
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Chrome
Accept: text/html
Connection: keep-alive
```

### Parts of Request

* **Request Line** → `GET /index.html HTTP/1.1`
* **Headers** → Host, User-Agent, Accept
* **Blank Line**
* **Body** (optional, mainly for POST/PUT)

---

## HTTP Response Format

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1200

<html>...</html>
```

### Parts of Response

* **Status Line**
* **Headers**
* **Blank Line**
* **Response Body**

## Common HTTP Methods

| Method  | Purpose                    |
| ------- | -------------------------- |

## Advantages

* Faster than HTTP/1.0 due to persistent connections.
* Supports virtual hosting using the `Host` header.
* Better caching mechanisms.
* Supports chunked transfer encoding.
* Widely supported by web browsers and servers.

---

## Disadvantages

* **Head-of-Line (HOL) Blocking:** Requests are processed sequentially on a connection.
* Text-based protocol, resulting in larger headers.
* No header compression.
* One request effectively blocks later ones on the same connection.
* Less efficient than HTTP/2 and HTTP/3.

---

## HTTP/1.0 vs HTTP/1.1

| Feature          | HTTP/1.0                             | HTTP/1.1                           |
| ---------------- | ------------------------------------ | ---------------------------------- |
| Connection       | New TCP connection for every request | Persistent (Keep-Alive) by default |
| Host Header      | Optional                             | Mandatory                          |
| Caching          | Basic                                | Improved                           |
| Chunked Transfer | No                                   | Yes                                |
| Pipelining       | No                                   | Yes                                |
| Performance      | Slower                               | Faster                             |

---

## Interview / Exam Definition (2–5 Marks)

> **HTTP/1.1 (HyperText Transfer Protocol version 1.1)** is an application-layer protocol used for communication between web clients and web servers over TCP. It introduced **persistent connections (Keep-Alive)**, the mandatory **Host** header for virtual hosting, **chunked transfer encoding**, improved caching, and support for request pipelining, making it more efficient than HTTP/1.0.
