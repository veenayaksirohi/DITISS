# Web server

> A **web server** is software (and sometimes the hardware running it) that receives HTTP/HTTPS requests from clients such as web browsers and returns web content like HTML pages, images, CSS, JavaScript files, or API responses.

### Simple Interview Definition

> A web server is a system that hosts web applications and delivers web pages or data to users over the internet using HTTP or HTTPS protocols.

### Example

When you enter a website URL in your browser:

1. The browser sends a request to the web server.
2. The web server processes the request.
3. It returns the requested webpage or data.
4. The browser displays the result.

### Popular Web Servers

* Apache HTTP Server
* Nginx
* Microsoft IIS

### One-Line Interview Answer

> A web server is software that handles client requests over HTTP/HTTPS and serves web pages, files, or application data to users.

# HTTP (HyperText Transfer Protocol)

## Definition

**HTTP (HyperText Transfer Protocol)** is an **application layer protocol** for communication between a **web client (browser)** and a **web server**. It defines how requests and responses are exchanged over the internet.

* **Default Port:** 80
* **Secure Version:** HTTPS (HTTP + SSL/TLS) uses Port 443
* **Protocol Type:** Stateless (each request is independent)

---

## How HTTP Works

```
Client (Browser)
       |
   HTTP Request
       |
       V
   Web Server
       |
  HTTP Response
       |
       V
Client displays webpage
```

### Example

**Request**

```
GET /index.html HTTP/1.1
Host: example.com
```

**Response**

```
HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>
```

# Evolution of HTTP

| Version      | Year | Features                                                       | Limitations                          |
| ------------ | ---- | -------------------------------------------------------------- | ------------------------------------ |
| **HTTP/0.9** | 1991 | Only GET method, plain HTML                                    | Very limited                         |
| **HTTP/1.0** | 1996 | Headers, status codes, POST method                             | New TCP connection for every request |
| **HTTP/1.1** | 1997 | Persistent connections, caching, chunked transfer, Host header | Head-of-line blocking                |
| **HTTP/2**   | 2015 | Multiplexing, header compression, server push                  | Still uses TCP                       |
| **HTTP/3**   | 2022 | Uses QUIC over UDP, faster connection setup, reduced latency   | Requires QUIC support                |

# Advantages of HTTP

* Simple and easy to implement
* Platform-independent
* Widely supported
* Supports caching
* Extensible using headers

---

# Limitations of HTTP

* Stateless protocol
* HTTP itself does not encrypt data (HTTPS does)
* Earlier versions had higher latency
* Performance issues with many separate requests (improved in HTTP/2 and HTTP/3)

# 5-Mark Exam Answer

**HTTP (HyperText Transfer Protocol)** is an **application layer protocol** used for communication between web browsers and web servers. It follows a **request-response** model and is **stateless**, meaning each request is handled independently. HTTP typically uses **port 80**, while its secure version, **HTTPS**, uses **port 443**.

**Evolution of HTTP:**

1. **HTTP/0.9 (1991):** Only the GET method; supported basic HTML pages.
2. **HTTP/1.0 (1996):** Introduced headers, status codes, and additional methods like POST and HEAD.
3. **HTTP/1.1 (1997):** Added persistent connections, caching, chunked transfer encoding, and the Host header.
4. **HTTP/2 (2015):** Introduced multiplexing, binary framing, header compression, and server push for improved performance.
5. **HTTP/3 (2022):** Uses QUIC over UDP instead of TCP, providing lower latency, faster connection setup, and better performance on unreliable networks.

**Conclusion:** HTTP has evolved from a simple protocol for transferring HTML documents into a fast, efficient, and secure protocol capable of supporting modern web applications.
