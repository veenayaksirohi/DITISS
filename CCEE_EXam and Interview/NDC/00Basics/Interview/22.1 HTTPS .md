# HTTPS (HyperText Transfer Protocol Secure)

## Definition

**HTTPS (HyperText Transfer Protocol Secure)** is the **secure version of HTTP**. It encrypts communication between a **web browser (client)** and a **web server** using **SSL/TLS** protocols.

* **HTTP** → Data is sent in plain text.
* **HTTPS** → Data is encrypted before transmission.

**Default Port:** **443**

---

## Why HTTPS is Needed

Without HTTPS:

* Passwords can be stolen.
* Credit card information can be intercepted.
* Login sessions can be hijacked.
* Data can be modified during transmission.

With HTTPS:

* Data remains confidential.
* Data integrity is maintained.
* Server identity is verified.

# Components Used in HTTPS

## 1. HTTP

Application layer protocol used for web communication.

Examples:

* GET
* POST
* PUT
* DELETE

---

## 2. SSL/TLS

**SSL (Secure Sockets Layer)** is an older security protocol.

**TLS (Transport Layer Security)** is the newer and more secure version.

Today almost all websites use **TLS**, though people often still say "SSL Certificate."

---

## 3. Digital Certificate

A digital certificate contains:

* Website name (Domain)
* Public Key
* Certificate Authority (CA) signature
* Expiry date

Example:

```
Website:
www.example.com

Public Key:
ABCD1234....

Issued By:
Let's Encrypt

Valid Until:
31-Dec-2026
```

---

## 4. Certificate Authority (CA)

A trusted organization that issues digital certificates.

Examples:

* Let's Encrypt
* DigiCert
* GlobalSign
* Sectigo

```
  |                               |
  |---3. Verify Certificate------>|
  |                               |

  |                               |

  |                               |
```

---

# Detailed HTTPS Working

## Step 1: User Enters URL

Example:

```
https://www.example.com
```

Browser contacts the web server.

---

## Step 2: TCP Connection

A TCP connection is established on **Port 443**.

```
Client
   |
TCP SYN
   |
Server
```

---

## Step 3: TLS Handshake Begins

The browser says:

```
Hello Server
I support:

TLS 1.2
TLS 1.3

Supported Cipher Suites
Random Number
```

This message is called:

**ClientHello**

---

## Step 4: ServerHello

Server replies with:

* TLS version
* Cipher suite
* Random number
* Digital certificate

```
ServerHello

TLS 1.3

Certificate

Public Key
```

---

## Step 5: Certificate Verification

Browser checks:

✔ Is certificate expired?

✔ Is certificate signed by a trusted CA?

✔ Is domain name correct?

✔ Is certificate revoked?

If all checks pass:

```
Certificate Trusted
```

Otherwise:

```
Your Connection is Not Private
```

---

## Step 6: Key Exchange

The browser generates a **Pre-Master Secret** and securely exchanges key material (using methods such as RSA in older TLS versions or, more commonly today, ephemeral Diffie–Hellman in TLS 1.3).

Both client and server independently derive the **same symmetric session key**.

---

## Step 7: Session Key Created

Now both sides possess the same **session key**.

Example:

```
Session Key

A7F9D4E2...
```

This key is used for fast encryption.

---

## Step 8: Secure Communication Starts

Now every HTTP request becomes HTTPS.

Example:

```
GET /login

↓

Encrypted

↓

Random unreadable data
```

Only the server can decrypt it.

---

# Encryption in HTTPS

HTTPS uses two types of encryption.

## 1. Asymmetric Encryption

Uses:

* Public Key
* Private Key

Used only during:

* Authentication
* Secure key exchange

Example:

```
Encrypt

Public Key

↓

Decrypt

Private Key
```

Slower but secure.

---

## 2. Symmetric Encryption

Uses the **same session key**.

```
Session Key

Encrypt

↓

Decrypt
```

Very fast.

Used for all actual data transfer after the handshake.

---

# TLS Handshake Flow

```
Client                          Server
 |                                 |
 |------ClientHello--------------->|
 |                                 |
 |<-----ServerHello----------------|
 |<-----Certificate----------------|
 |                                 |
 |----Key Exchange---------------->|
 |                                 |
 |<---Handshake Complete-----------|
 |                                 |
 |====Encrypted Data==============>|
```

---

# What Happens After Handshake?

Browser sends:

```
GET /index.html
```

Instead of plain text:

```
GET /index.html

↓

Encrypted Bytes
```

Server decrypts it.

Processes request.

Returns encrypted response.

# HTTPS Security Services

| Security Service | Purpose                                                           |
| ---------------- | ----------------------------------------------------------------- |
| Confidentiality  | Encryption prevents unauthorized reading                          |
| Integrity        | Detects if data is altered in transit                             |
| Authentication   | Confirms the server's identity                                    |
| Non-repudiation  | Can be supported using digital signatures in appropriate contexts |

---

# Advantages of HTTPS

* Encrypts all communication.
* Protects passwords and personal information.
* Prevents eavesdropping.
* Prevents Man-in-the-Middle (MITM) attacks when certificates are properly validated.
* Builds user trust (padlock icon).
* Improves SEO (search engines favor HTTPS).
* Required for many modern browser features (service workers, geolocation, etc.).

---

# Disadvantages of HTTPS

* Slightly more CPU usage due to encryption (much less significant with modern hardware).
* Requires obtaining and managing TLS certificates.
* Certificate renewal and configuration require administration.
* Improper certificate configuration can cause browser warnings.

---

# HTTP vs HTTPS

| Feature              | HTTP                        | HTTPS                              |
| -------------------- | --------------------------- | ---------------------------------- |
| Full Form            | HyperText Transfer Protocol | HyperText Transfer Protocol Secure |
| Security             | No encryption               | Encrypted using TLS                |
| Port                 | 80                          | 443                                |
| Encryption           | No                          | Yes                                |
| Authentication       | No                          | Yes (server authentication)        |
| Data Privacy         | No                          | Yes                                |
| Integrity            | No                          | Yes                                |
| Certificate Required | No                          | Yes                                |
| URL Prefix           | `http://`                   | `https://`                         |
| Browser Padlock      | No                          | Yes                                |

## Exam Points (5 Marks)

* HTTPS is the secure version of HTTP.
* Uses **TLS** to encrypt communication.
* Runs on **port 443**.
* Provides **Confidentiality, Integrity, and Authentication**.
* Uses a **digital certificate** issued by a **Certificate Authority (CA)**.
* Performs a **TLS handshake** to authenticate the server and establish a **symmetric session key**.
* After the handshake, all communication is encrypted using the session key, making HTTPS both secure and efficient.
