# 1. Web Application Security Risks

## What is Web Application Security?

Web Application Security is the practice of protecting websites and web applications from attacks that can compromise:

* Confidentiality (Data secrecy)
* Integrity (Data correctness)
* Availability (System accessibility)

### Security Goals (CIA Triad)

| Goal            | Meaning                           | Example             |
| --------------- | --------------------------------- | ------------------- |
| Confidentiality | Prevent unauthorized access       | Password protection |
| Integrity       | Prevent unauthorized modification | Database validation |
| Availability    | Keep services accessible          | DDoS protection     |

---

# Why Web Applications Are Targeted

Most organizations expose applications to the Internet.

Examples:

* Banking portals
* E-commerce websites
* Social media
* Government services
* Cloud applications

Attackers target them because they contain:

* User credentials
* Financial data
* Personal information
* Business secrets

# Common Web Application Security Risks

---

## 1. Injection Attacks

Occurs when untrusted data is sent to an interpreter.

Examples:

### SQL Injection

```sql
SELECT * FROM users
WHERE username='admin'
AND password='123'
```

Attacker:

```sql
' OR '1'='1
```

Result:

Authentication bypass.

---

### Command Injection

```bash
ping 127.0.0.1
```

Input:

```bash
127.0.0.1 && whoami
```

---

### LDAP Injection

Manipulating LDAP queries.

---

### XPath Injection

Manipulating XML queries.

---

## 2. Broken Authentication

Occurs when authentication mechanisms are weak.

Examples:

* Weak passwords
* Session fixation
* Session hijacking
* Credential stuffing

Impact:

* Account takeover

---

## 3. Broken Access Control

Users can access resources they shouldn't.

Example:

```http
/profile?id=5
```

Changing:

```http
/profile?id=1
```

Accessing another user's data.

Also known as:

### IDOR

(Insecure Direct Object Reference)

---

## 4. Sensitive Data Exposure

Sensitive data not properly protected.

Examples:

* Plaintext passwords
* HTTP instead of HTTPS
* Weak encryption

---

## 5. Security Misconfiguration

Incorrect settings expose systems.

Examples:

* Default passwords
* Open directories
* Debug mode enabled
* Unnecessary services

---

## 6. Cross-Site Scripting (XSS)

Attacker injects JavaScript into web pages.

### Stored XSS

Stored permanently.

Example:

Comment section.

---

### Reflected XSS

Returned immediately.

Example:

Search field.

---

### DOM XSS

Executed through client-side JavaScript.

---

## 7. Cross-Site Request Forgery (CSRF)

Forces victim to perform unwanted actions.

Example:

Victim already logged in.

Attacker sends:

```html
<img src="https://bank.com/transfer?amount=10000">
```

Browser sends authenticated request.

---

## 8. Insecure Deserialization

Unsafe object deserialization.

Can lead to:

* RCE
* Authentication bypass

---

## 9. SSRF (Server-Side Request Forgery)

Server makes requests on behalf of attacker.

Example:

```http
http://localhost/admin
```

Impact:

* Internal network access
* Cloud metadata theft

---

## 10. File Inclusion Vulnerabilities

### LFI

Local File Inclusion

```php
?page=../../etc/passwd
```

### RFI

Remote File Inclusion

Including external code.

---

## 11. File Upload Vulnerabilities

Uploading:

```php
shell.php
```

Can lead to:

* Remote Code Execution

---

## 12. Clickjacking

Tricking users into clicking hidden elements.

Defense:

```http
X-Frame-Options: DENY
```

---

## 13. Security Logging Failures

Insufficient logging and monitoring.

Impact:

Attack remains undetected.

# STRIDE Model (VERY IMPORTANT)

| Threat | Meaning                |
| ------ | ---------------------- |
| S      | Spoofing               |
| T      | Tampering              |
| R      | Repudiation            |
| I      | Information Disclosure |
| D      | Denial of Service      |
| E      | Elevation of Privilege |

---

## Spoofing

Pretending to be another user.

Example:

* Credential theft
* Session hijacking

---

## Tampering

Unauthorized modification.

Example:

* Changing requests
* Data manipulation

---

## Repudiation

User denies actions.

Solution:

* Logging
* Audit trails

---

## Information Disclosure

Data leakage.

Example:

* Password exposure
* Database leaks

---

## Denial of Service

Resource exhaustion.

Example:

* DDoS attacks

---

## Elevation of Privilege

Normal user becomes admin.

Example:

* Broken access control

---

# DREAD Risk Model

| Factor | Meaning         |
| ------ | --------------- |
| D      | Damage          |
| R      | Reproducibility |
| E      | Exploitability  |
| A      | Affected Users  |
| D      | Discoverability |

Used for risk scoring.

---

* Finds issues early
* Reduces cost
* Improves architecture
* Enhances security posture

# Major Burp Suite Features

---

## 1. Proxy

Intercepts browser traffic.

Functions:

* Capture requests
* Modify requests
* Analyze responses

---

## 2. Target

Shows:

* Site map
* Application structure

Useful for reconnaissance.

---

## 3. Repeater

Manually resend requests.

Use Cases:

* SQL Injection
* XSS testing
* Access control testing

---

## 4. Intruder

Automated payload testing.

Attack Types:

### Sniper

One parameter at a time.

### Battering Ram

Same payload everywhere.

### Pitchfork

Multiple payload lists simultaneously.

### Cluster Bomb

All combinations.

---

## 5. Decoder

Encode/decode:

* URL
* Base64
* HTML
* Hex

---

## 6. Comparer

Compare:

* Requests
* Responses

Useful during testing.

---

## 7. Sequencer

Tests randomness of:

* Session IDs
* Tokens

---

## 8. Scanner (Professional)

Automated vulnerability scanning.

Detects:

* SQLi
* XSS
* SSRF
* Misconfigurations

---

## 9. Extender

Adds plugins/extensions.

Examples:

* Autorize
* Logger++
* JWT Editor

---

## 10. Collaborator

Detects:

* Blind SSRF
* Blind XXE
* Blind RCE
