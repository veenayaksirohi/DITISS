# Buffer Overflows and Input Validation (Placement + Interview + Exam Notes)

---

# 1. Introduction

## What is a Buffer?

A **buffer** is a temporary memory storage area used to hold data while it is being transferred between locations.

Examples:

* Keyboard input buffer
* Network packet buffer
* File read/write buffer

```c
char name[10];
```

Here, `name` is a buffer capable of storing 10 characters.

---

# 2. What is Buffer Overflow?

A **Buffer Overflow** occurs when a program writes more data into a buffer than it can hold.

### Example

```c
char name[10];
gets(name);
```

Input:

```text
Harshal123456789
```

Buffer size = 10

Input size = 16

Extra characters overwrite adjacent memory.

---

# Why is Buffer Overflow Dangerous?

Can cause:

1. Program crash
2. Data corruption
3. Unauthorized access
4. Code execution
5. Privilege escalation
6. System compromise

---

# Memory Layout of a Process

Typical memory structure:

```text
+----------------+
| Stack          |
+----------------+
| Heap           |
+----------------+
| Data Segment   |
+----------------+
| Code Segment   |
+----------------+
```

Buffer overflows commonly occur in:

* Stack
* Heap

---

# 3. Types of Buffer Overflow

## A. Stack Buffer Overflow

Occurs when excess data overwrites stack memory.

Example:

```c
void func()
{
    char buf[8];
    gets(buf);
}
```

Input:

```text
AAAAAAAAAAAAAAAAAAAA
```

May overwrite:

* Local variables
* Frame pointer
* Return address

---

## B. Heap Buffer Overflow

Occurs when dynamically allocated memory is exceeded.

```c
char *buf = malloc(8);
strcpy(buf,"AAAAAAAAAAAAAAAA");
```

Overflow corrupts nearby heap structures.

---

## C. Global Buffer Overflow

Global variable memory gets overwritten.

```c
char buffer[8];
```

Stored in Data Segment.

---

# 4. Stack Overflow vs Buffer Overflow

| Stack Overflow           | Buffer Overflow                   |
| ------------------------ | --------------------------------- |
| Stack memory exhaustion  | Writing beyond buffer             |
| Usually due to recursion | Usually due to bad input handling |
| May crash application    | May lead to code execution        |

---

# 5. How Buffer Overflow Happens

### Unsafe Input

```c
gets(name);
```

No length checking.

---

### Unsafe Copy

```c
strcpy(dest,src);
```

Copies everything.

---

### Unsafe Concatenation

```c
strcat(dest,src);
```

No boundary check.

---

### Unsafe Formatting

```c
sprintf(buf,"%s",userInput);
```

Can exceed buffer size.

---

# 7. Buffer Overflow Attack

Attacker provides large input.

Example:

```text
AAAAAAAAAAAAAAAAAAAAAAAA
```

Overflow overwrites:

```text
Buffer
Saved Frame Pointer
Return Address
```

Attacker may control execution flow.

---

# Classic Attack Flow

```text
Input
 ↓
Buffer Overflow
 ↓
Overwrite Return Address
 ↓
Redirect Execution
 ↓
Malicious Code Executes
```

---

# 8. Return Address Overwrite

Function Call:

```text
Main
 ↓
Function
```

Stack stores:

```text
Return Address
```

Overflow changes it:

```text
Original:
0x12345678

Attacker:
0xDEADBEEF
```

Program jumps to attacker-controlled location.

---

# 9. Shellcode

Shellcode = machine code injected by attacker.

Purpose:

* Open shell
* Create user
* Execute commands

Historically:

```text
Buffer
NOP Sled
Shellcode
```

---

# 10. NOP Sled

NOP = No Operation

```assembly
90 90 90 90
```

Processor slides through NOPs until shellcode.

```text
[NOP][NOP][NOP][Shellcode]
```

Improves attack success rate.

---

# 11. Heap Overflow Attack

Overflow heap chunk:

```text
Chunk A
Chunk B
Chunk C
```

Overflow from A into B.

Effects:

* Memory corruption
* Program crash
* Code execution

---

# 12. Integer Overflow Leading to Buffer Overflow

Example:

```c
int size = userInput * 4;
```

Large value causes integer wraparound.

Small memory allocated.

Large data copied.

Result:

```text
Integer Overflow
 ↓
Small Allocation
 ↓
Buffer Overflow
```

---

# 13. Off-by-One Error

Writing one extra byte.

Example:

```c
char buf[8];

for(i=0;i<=8;i++)
```

Should be:

```c
i<8
```

Very common exam question.

---

# 14. Input Validation

## Definition

Process of ensuring user input is:

* Correct
* Expected
* Safe

Before processing.

---

# Why Input Validation?

Prevents:

* Buffer Overflow
* SQL Injection
* XSS
* Command Injection
* Path Traversal

---

# 15. Types of Validation

## A. Length Validation

Check input size.

Example:

```c
if(strlen(name)>20)
```

Reject input.

---

## B. Type Validation

Expected:

```text
Age = Integer
```

Reject:

```text
Age = ABC
```

---

## C. Range Validation

Example:

```text
Marks 0-100
```

Reject:

```text
150
```

---

## D. Format Validation

Email:

```text
abc@gmail.com
```

Validate structure.

---

## E. Whitelist Validation

Allow only known good values.

```text
A-Z
0-9
```

Best approach.

---

## F. Blacklist Validation

Block bad values.

```text
<script>
DROP TABLE
```

Weak approach.

---

# 16. Whitelist vs Blacklist

| Whitelist        | Blacklist       |
| ---------------- | --------------- |
| Allow good input | Block bad input |
| More secure      | Less secure     |
| Recommended      | Not recommended |

### Exam Point

✅ Whitelisting is preferred.

---

# 17. Secure Coding Practices

## Validate Input

```c
if(strlen(input)<20)
```

---

## Check Bounds

```c
for(i=0;i<MAX;i++)
```

---

## Use Safe APIs

```c
fgets()
snprintf()
```

---

## Avoid gets()

Never use:

```c
gets()
```

---

## Use Compiler Protections

Examples:

* Stack Canaries
* ASLR
* DEP

---

# 18. Modern Buffer Overflow Defenses

## A. Stack Canaries

Random value placed before return address.

```text
Buffer
Canary
Return Address
```

Overflow changes canary.

Program terminates.

---

## B. ASLR

Address Space Layout Randomization

Randomizes memory addresses.

Makes attack difficult.

---

## C. DEP / NX Bit

Data Execution Prevention

Prevents executing code in data memory.

---

## D. PIE

Position Independent Executable

Changes executable location.

Works with ASLR.

---

# 19. ASLR + DEP + Canary

Modern protection combination:

```text
Canary
+
ASLR
+
DEP
```

Strong defense against classic buffer overflow attacks.

---

# 20. Secure Input Handling Example

Unsafe:

```c
char name[10];
gets(name);
```

Safe:

```c
char name[10];
fgets(name,sizeof(name),stdin);
```

# Exam Important Points (One-Liners)

⭐ Buffer Overflow = Writing beyond buffer boundary.

⭐ Stack Buffer Overflow is most commonly tested.

⭐ `gets()` is unsafe and deprecated.

⭐ `fgets()` is safer.

⭐ `strncpy()` safer than `strcpy()`.

⭐ Whitelisting > Blacklisting.

⭐ ASLR randomizes memory layout.

⭐ DEP prevents code execution from data pages.

⭐ Stack Canary detects stack corruption.

⭐ Off-by-One errors can cause overflows.

⭐ Input validation is first line of defense.

⭐ Buffer overflow may lead to Remote Code Execution (RCE).

⭐ Heap overflow affects dynamically allocated memory.

⭐ Length validation prevents many overflow attacks.
