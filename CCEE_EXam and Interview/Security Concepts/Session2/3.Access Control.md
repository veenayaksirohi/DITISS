# Access Control – Complete Notes for Placements, Exams & Security Interviews

---

# 1. What is Access Control?

**Access Control** is a security mechanism that determines:

* **Who** can access a resource
* **What** resources they can access
* **What actions** they can perform
* **Under what conditions** access is allowed

### Formula

**Subject → Action → Object**

Example:

* User Harsh (Subject)
* Reads (Action)
* Employee Database (Object)

---

# 2. Objectives of Access Control

### 1. Confidentiality

Prevent unauthorized disclosure of information.

### 2. Integrity

Prevent unauthorized modification of data.

### 3. Availability

Ensure authorized users can access resources when needed.

### 4. Accountability

Track actions performed by users.

---

# 3. Access Control Components

## Subject

Entity requesting access.

Examples:

* User
* Process
* Application
* Device

---

## Object

Resource being accessed.

Examples:

* File
* Database
* Network
* Application
* API

---

## Permission

Allowed action.

Examples:

* Read
* Write
* Execute
* Delete
* Modify

---

## Policy

Rules defining access rights.

Example:

* Employees can view payroll.
* HR can modify payroll.

---

# 4. Access Control Process

### Step 1: Identification

User claims identity.

Example:

```
Username: Harsh
```

---

### Step 2: Authentication

Verify identity.

Methods:

* Password
* OTP
* Smart Card
* Biometrics

---

### Step 3: Authorization

Determine permissions.

Example:

```
Can read file
Cannot delete file
```

---

### Step 4: Accountability

Log actions.

Example:

```
Harsh downloaded report.pdf
```

---

# 5. AAA Framework

Very Important

| Component      | Meaning              |
| -------------- | -------------------- |
| Authentication | Verify identity      |
| Authorization  | Verify permissions   |
| Accounting     | Logging and auditing |

### Example

Login → Authentication

Check permissions → Authorization

Record activity → Accounting

# 8. Access Control Models

Most Important Interview Topic

---

# A. DAC (Discretionary Access Control)

Owner controls permissions.

Example:

```
File Owner grants access.
```

### Advantages

* Flexible
* Easy to manage

### Disadvantages

* Less secure
* Permissions may spread

### Example

Windows File Permissions

---

# B. MAC (Mandatory Access Control)

Central authority controls permissions.

Users cannot change permissions.

### Security Labels

Examples:

* Top Secret
* Secret
* Confidential
* Public

### Advantages

* Highly secure

### Disadvantages

* Less flexible

### Example

Military Systems

---

# C. RBAC (Role-Based Access Control)

Permissions assigned based on roles.

### Example

Admin

* Read
* Write
* Delete

Employee

* Read

### Advantages

* Easy management
* Scalable

### Example

Corporate Networks

---

# D. ABAC (Attribute-Based Access Control)

Decisions based on attributes.

Attributes:

### User

* Department
* Designation

### Resource

* Classification

### Environment

* Time
* Location

### Example

```
Allow access if:
Department = HR
AND Time < 6 PM
```

### Advantages

* Highly flexible

### Disadvantages

* Complex implementation

---

# 9. Comparison of Access Control Models

| Feature        | DAC     | MAC      | RBAC       | ABAC      |
| -------------- | ------- | -------- | ---------- | --------- |
| Owner Controls | Yes     | No       | No         | No        |
| Security       | Low     | High     | Medium     | High      |
| Flexibility    | High    | Low      | Medium     | Very High |
| Complexity     | Low     | Medium   | Medium     | High      |
| Example        | Windows | Military | Enterprise | Cloud     |

# 10. Access Control Matrix

Shows permissions.

| User  | File A | File B |
| ----- | ------ | ------ |
| User1 | Read   | Write  |
| User2 | Write  | Read   |

Used to define access rights.

---

# 11. Principle of Least Privilege (PoLP)

Very Important

Users receive minimum permissions required.

Example:

Employee needs:

✅ Read reports

❌ Delete database

Benefits:

* Reduced attack surface
* Reduced insider threats

---

# 12. Need-to-Know Principle

User gets access only if required.

Example:

Finance employee cannot access HR records.

---

# 13. Separation of Duties (SoD)

No single person controls entire process.

Example:

Person A creates payment.

Person B approves payment.

Benefits:

* Prevent fraud
* Improve accountability

---

# 14. Privileged Access Management (PAM)

Controls high-privilege accounts.

Examples:

* Administrator
* Root User
* Domain Admin

Features:

* Credential vaulting
* Session monitoring
* Password rotation

---

# 15. Identity and Access Management (IAM)

Framework managing identities and permissions.

Functions:

* User provisioning
* Authentication
* Authorization
* Auditing

Examples:

* Microsoft Entra ID
* Okta

---

# 16. Single Sign-On (SSO)

Login once and access multiple applications.

Example:

Google Account → Gmail + Drive + YouTube

Advantages:

* Better user experience
* Fewer passwords

Risk:

* One account compromise affects multiple services.

---

# 17. Federation

Trust relationship between organizations.

Example:

University login used to access third-party services.

Protocols:

* SAML
* OAuth
* OpenID Connect

---

# 18. Access Control Attacks

---

## 1. Privilege Escalation

User gains higher permissions.

### Vertical

User → Admin

### Horizontal

User A → User B

---

## 2. Broken Access Control

User accesses unauthorized resources.

Example:

```
/account?id=100
/account?id=101
```

Access another user's account.

OWASP Top 10 issue.

---

## 3. IDOR

Insecure Direct Object Reference

Example:

```
/profile?id=10
```

Change:

```
/profile?id=11
```

Access another user's data.

---

## 4. Session Hijacking

Attacker steals session token.

Impact:

* Account takeover

---

## 5. Password Attacks

* Brute Force
* Dictionary Attack
* Credential Stuffing

---

## 6. Insider Threat

Authorized user abuses privileges.

---

# 19. Access Control Technologies

## ACL (Access Control List)

Permissions attached to resource.

Example:

```
File A:
User1 = Read
User2 = Write
```

---

## Capability List

Permissions attached to user.

Example:

```
User1:
Read File A
Write File B
```

---

# 20. Access Reviews

Periodic verification of permissions.

Questions:

* Does employee still need access?
* Has employee left company?

Benefits:

* Reduce excessive privileges

---

# 21. Zero Trust Access Control

Principle:

### Never Trust, Always Verify

Checks:

* Identity
* Device
* Location
* Risk Score

Every request is verified.
