# Section 2 : Report Management, Patch Management & Risk Management

# 1. Report Management

## What is Report Management?

Report Management in VAPT is the process of:

* Documenting vulnerabilities
* Explaining risks
* Providing proof of concept (PoC)
* Suggesting remediation steps
* Tracking fixes and retesting

A VAPT report is the final deliverable given to the client or organization.

---

# Objectives of Report Management

* Communicate findings clearly
* Help management understand risks
* Help technical teams fix vulnerabilities
* Maintain audit/compliance records
* Track remediation progress

---

# Types of VAPT Reports

| Report Type        | Purpose                              |
| ------------------ | ------------------------------------ |
| Executive Report   | High-level summary for management    |
| Technical Report   | Detailed technical findings          |
| Compliance Report  | Meets PCI-DSS, ISO 27001, HIPAA etc. |
| Risk Report        | Risk severity and business impact    |
| Remediation Report | Fixes and recommendations            |

---

# Components of a VAPT Report

# 1. Executive Summary

Contains:

* Overall security posture
* Major vulnerabilities
* Risk overview
* Business impact

Non-technical language is used.

---

# 2. Scope of Testing

Defines:

* IP ranges
* Applications tested
* Test duration
* Methodology used

Example:

```text id="pkjlwm"
Scope:
192.168.1.0/24
example.com
Web APIs
```

---

# 3. Methodology

Describes testing process.

## Common Methodologies

* OWASP Foundation Testing Guide
* Open Web Application Security Project
* PTES
* NIST
* OSSTMM

---

# 4. Vulnerability Details

Each vulnerability contains:

| Field          | Description              |
| -------------- | ------------------------ |
| Title          | Vulnerability name       |
| Severity       | Critical/High/Medium/Low |
| Description    | Explanation              |
| Affected Asset | Impacted system          |
| CVE            | Vulnerability ID         |
| CVSS Score     | Severity score           |
| Evidence       | Screenshot/logs          |
| Remediation    | Fix recommendations      |

---

# 5. Proof of Concept (PoC)

Shows exploitation evidence.

Examples:

* Screenshots
* Request/response
* Exploit output
* Payloads

---

# 6. Risk Rating

## Common Severity Levels

| Severity      | Meaning                         |
| ------------- | ------------------------------- |
| Critical      | Immediate exploitation possible |
| High          | Serious impact                  |
| Medium        | Moderate risk                   |
| Low           | Minor risk                      |
| Informational | No direct impact                |

---

# 7. Remediation Recommendations

Provides fixes like:

* Patch systems
* Disable vulnerable services
* Use MFA
* Update libraries
* Change configurations

---

# 8. Conclusion

Final security assessment summary.

---

# Report Writing Best Practices

* Use simple language
* Include screenshots
* Avoid false positives
* Prioritize vulnerabilities
* Provide actionable fixes
* Mention business impact

---

# 2. Patch Management

# What is Patch Management?

Patch Management is the process of:

* Identifying
* Testing
* Deploying
* Verifying updates/patches

to fix:

* Security vulnerabilities
* Bugs
* Stability issues

---

# Purpose of Patch Management

* Fix vulnerabilities
* Prevent exploitation
* Improve performance
* Maintain compliance
* Reduce attack surface

---

# Types of Patches

| Patch Type     | Purpose                 |
| -------------- | ----------------------- |
| Security Patch | Fixes vulnerabilities   |
| Bug Fix Patch  | Fixes software bugs     |
| Hotfix         | Emergency fix           |
| Firmware Patch | Hardware device updates |
| Feature Update | Adds new functionality  |

---

# Patch Management Life Cycle

```text id="nwl2fh"
Asset Discovery
      ↓
Vulnerability Identification
      ↓
Patch Evaluation
      ↓
Testing
      ↓
Deployment
      ↓
Verification
      ↓
Documentation
```

---

# Steps in Patch Management

# 1. Asset Inventory

Identify:

* Systems
* Applications
* Servers
* Devices

---

# 2. Vulnerability Assessment

Find missing patches using:

* Nessus
* OpenVAS
* Qualys

---

# 3. Patch Prioritization

Priority based on:

* CVSS score
* Exploit availability
* Business impact
* Internet exposure

---

# 4. Patch Testing

Testing ensures:

* Compatibility
* Stability
* No downtime

Usually tested in staging environment.

---

# 5. Patch Deployment

Deployment methods:

* Manual
* Automated
* Centralized patch management

---

# 6. Verification

Verify successful installation.

Commands:

## Windows

```powershell id="1ye7mb"
wmic qfe list
```

## Linux

```bash id="opplbt"
yum updateinfo
apt list --upgradable
```

---

# 7. Documentation

Maintain:

* Patch logs
* Change records
* Compliance records

---

# Patch Management Tools

| Tool                            | Platform         |
| ------------------------------- | ---------------- |
| WSUS                            | Windows          |
| SCCM                            | Enterprise       |
| ManageEngine Patch Manager Plus | Cross-platform   |
| Ansible                         | Linux automation |

---

# Patch Management Challenges

* Downtime risk
* Legacy systems
* Patch conflicts
* Testing delays
* Incomplete inventory

---

# Patch Management Best Practices

* Patch critical systems first
* Maintain backups
* Use staging environment
* Automate updates
* Regular vulnerability scanning
* Remove unsupported software

---

# Zero-Day Vulnerabilities

## What is Zero-Day?

A vulnerability:

* Unknown to vendor
* No patch available yet

Requires:

* Temporary mitigation
* IPS/WAF rules
* Monitoring

---

# Patch Tuesday

Microsoft releases security patches monthly called:

* Patch Tuesday

Usually:

* Second Tuesday of every month

---

# 3. Risk Management

# What is Risk Management?

Risk Management is the process of:

* Identifying risks
* Assessing impact
* Reducing threats
* Protecting assets

---

# Risk Formula

```text id="v9frwg"
Risk = Threat × Vulnerability × Impact
```

---

# Key Risk Terms

| Term          | Meaning           |
| ------------- | ----------------- |
| Asset         | Valuable resource |
| Threat        | Potential danger  |
| Vulnerability | Weakness          |
| Risk          | Chance of damage  |
| Impact        | Business damage   |
| Mitigation    | Reducing risk     |

---

# Risk Management Process

```text id="ehkbzv"
Risk Identification
        ↓
Risk Assessment
        ↓
Risk Analysis
        ↓
Risk Treatment
        ↓
Risk Monitoring
        ↓
Risk Review
```

---

# Types of Risks

| Risk Type         | Example         |
| ----------------- | --------------- |
| Cyber Risk        | Malware attack  |
| Operational Risk  | System failure  |
| Financial Risk    | Monetary loss   |
| Compliance Risk   | Legal penalties |
| Reputational Risk | Brand damage    |

---

# Risk Assessment

# Qualitative Risk Assessment

Uses labels:

* High
* Medium
* Low

---

# Quantitative Risk Assessment

Uses numerical values:

* Cost impact
* Probability
* Loss expectancy

---

# Risk Matrix

| Likelihood | Impact | Risk     |
| ---------- | ------ | -------- |
| High       | High   | Critical |
| High       | Medium | High     |
| Medium     | Medium | Medium   |
| Low        | Low    | Low      |

---

# Risk Treatment Methods

| Method     | Meaning                |
| ---------- | ---------------------- |
| Mitigation | Reduce risk            |
| Avoidance  | Eliminate activity     |
| Transfer   | Shift risk (insurance) |
| Acceptance | Accept risk            |

---

# Risk Management Frameworks

| Framework | Purpose                 |
| --------- | ----------------------- |
| NIST      | Cybersecurity framework |
| ISO 27001 | Information security    |
| FAIR      | Risk analysis           |
| COBIT     | IT governance           |

---

# Risk Scoring Factors

* Asset value
* Exploitability
* Exposure
* Data sensitivity
* Threat likelihood

---

# Risk Register

A document containing:

* Risks
* Owners
* Severity
* Mitigation status

Example:

| Risk          | Severity | Owner         | Status |
| ------------- | -------- | ------------- | ------ |
| SQL Injection | Critical | Security Team | Open   |

---

# Residual Risk

Risk remaining after controls are implemented.

---

# Risk Appetite

Amount of risk organization is willing to accept.

# Important Interview Questions

## Report Management

### Why is reporting important in VAPT?

It communicates vulnerabilities and remediation to stakeholders.

### What should a good VAPT report contain?

Findings, evidence, impact, severity, remediation.

---

## Patch Management

### What is a hotfix?

Emergency patch for critical issue.

### Why should patches be tested first?

To avoid downtime or compatibility problems.

### What is Patch Tuesday?

Monthly security patch release by Microsoft.

---

## Risk Management

### Difference between threat and vulnerability?

Threat is danger; vulnerability is weakness.

### What is residual risk?

Remaining risk after controls.

### What is risk mitigation?

Reducing likelihood or impact of risk.
