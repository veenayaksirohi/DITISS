# 1. Application Security Testing Overview

Application Security Testing (AST) is the process of finding security vulnerabilities in software before attackers exploit them.

## Types

| Type | Full Form                                | Testing Method      |
| ---- | ---------------------------------------- | ------------------- |
| SAST | Static Application Security Testing      | White Box           |
| DAST | Dynamic Application Security Testing     | Black Box           |
| IAST | Interactive Application Security Testing | Gray Box            |
| SCA  | Software Composition Analysis            | Dependency Analysis |
| RASP | Runtime Application Self Protection      | Runtime Protection  |

---

# 2. SAST (Static Application Security Testing)

## Definition

SAST analyzes source code, bytecode, or binaries without executing the application.

It scans the code and identifies security weaknesses during development.

### Think:

> Looking at the blueprint of a house before construction.

---

## How SAST Works

1. Developer writes code
2. SAST tool scans source code
3. Data flow analysis performed
4. Vulnerable patterns identified
5. Report generated

```
Source Code
      ↓
 SAST Scanner
      ↓
 Vulnerability Detection
      ↓
 Report
```

# SAST Detects

### Injection Vulnerabilities

```php
$query = "SELECT * FROM users WHERE id=".$_GET['id'];
```

Detects:

* SQL Injection
* No Input Validation

---

### Hardcoded Secrets

```python
password = "admin123"
api_key = "abcd1234"
```

---

### Buffer Overflow

```c
char buf[10];
gets(buf);
```

---

### Command Injection

```php
system($_GET['cmd']);
```

---

### XSS

```javascript
document.write(userInput);
```

---

### Path Traversal

```php
include($_GET['page']);
```

---

### Weak Cryptography

```java
MD5(password)
SHA1(password)
```

---

# Practical SAST Using Semgrep

Install

```bash
pip install semgrep
```

Scan Current Project

```bash
semgrep scan
```

Scan for Security Rules

```bash
semgrep --config=p/security-audit .
```

Scan Specific File

```bash
semgrep scan app.py
```

# DAST (Dynamic Application Security Testing)

## Definition

DAST analyzes a running application from outside.

No source code required.

### Think:

> Testing a completed house by entering it and checking for weaknesses.

---

# How DAST Works

1. Application runs
2. Scanner sends requests
3. Responses analyzed
4. Vulnerabilities identified

```
Running App
      ↑
      ↓
DAST Scanner
      ↓
Attack Simulation
      ↓
Report
```

# DAST Detects

## SQL Injection

Request

```http
?id=1'
```

Response

```sql
SQL syntax error
```

Vulnerability found.

---

## XSS

```html
<script>alert(1)</script>
```

Injected into forms.

---

## Authentication Issues

Checks:

* Weak passwords
* Session fixation
* Session timeout

---

## Security Headers Missing

Checks:

```http
X-Frame-Options
CSP
HSTS
```

---

## Open Redirect

```text
redirect=evil.com
```

---

## Directory Traversal

```text
../../etc/passwd
```

---

## Sensitive Information Disclosure

Examples:

* Stack traces
* API keys
* Debug messages

# SAST vs DAST

| Feature            | SAST   | DAST    |
| ------------------ | ------ | ------- |
| Testing            | Static | Dynamic |
| Code Required      | Yes    | No      |
| White Box          | Yes    | No      |
| Black Box          | No     | Yes     |
| Early Detection    | Yes    | No      |
| Runtime Issues     | No     | Yes     |
| Exact Code Line    | Yes    | No      |
| Production Testing | No     | Yes     |
| Speed              | Fast   | Slower  |
