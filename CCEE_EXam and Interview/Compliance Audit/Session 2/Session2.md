# Session 3: Security Evaluation & Assurance (2T) – Complete Exam Notes

---

# 1. Security Evaluation

## Definition

Security Evaluation is the process of assessing a system, product, or software to determine whether it meets specified security requirements and provides adequate protection against threats.

### Objectives

* Verify security controls are correctly implemented.
* Identify vulnerabilities and weaknesses.
* Ensure compliance with standards.
* Measure trustworthiness of a system.
* Provide assurance to users and organizations.

### Why Security Evaluation is Important?

* Protect sensitive information.
* Reduce security risks.
* Ensure regulatory compliance.
* Improve confidence in IT systems.
* Support secure deployment decisions.

---

# 2. Evaluation Process

Security evaluation follows a structured process to determine whether a product satisfies security requirements.

## Steps in Evaluation Process

### 1. Define Security Requirements

* Identify assets to protect.
* Define security objectives.
* Determine evaluation criteria.

### 2. Analyze System Design

* Review architecture.
* Examine security mechanisms.
* Verify design documentation.

### 3. Test Security Controls

* Authentication testing.
* Access control testing.
* Encryption verification.
* Vulnerability assessment.

### 4. Evaluate Results

* Compare findings against requirements.
* Identify security gaps.
* Assess effectiveness.

### 5. Certification / Reporting

* Prepare evaluation report.
* Assign assurance level.
* Recommend improvements.

---

# 3. Evaluation Phases

Security evaluation generally consists of multiple phases.

---

## Phase 1: Planning

### Activities

* Define scope.
* Determine objectives.
* Select evaluation criteria.

### Deliverables

* Evaluation plan.
* Security requirements document.

---

## Phase 2: Documentation Review

### Activities

* Review system design.
* Examine security policies.
* Verify architecture documentation.

### Purpose

Ensure documentation supports claimed security features.

---

## Phase 3: Functional Testing

### Activities

* Test security functions.
* Verify access controls.
* Check authentication mechanisms.

### Purpose

Confirm system performs intended security operations.

---

## Phase 4: Vulnerability Assessment

### Activities

* Identify weaknesses.
* Penetration testing.
* Threat analysis.

### Purpose

Determine resistance against attacks.

---

## Phase 5: Assurance Assessment

### Activities

* Review development process.
* Examine configuration management.
* Evaluate testing evidence.

### Purpose

Measure confidence in system security.

---

## Phase 6: Reporting & Certification

### Activities

* Document findings.
* Assign assurance level.
* Provide recommendations.

### Output

Final Evaluation Report.

---

# 4. Assurance

## Definition

Assurance is the degree of confidence that security measures correctly enforce security policies and protect information.

### Simple Definition for Exam

> Assurance means confidence that a system is secure and functions as intended.

---

## Types of Assurance

### 1. Design Assurance

Confidence that system design is secure.

### 2. Implementation Assurance

Confidence that security mechanisms are correctly implemented.

### 3. Operational Assurance

Confidence that security continues during operation.

---

# 5. Assurance – 7 Evaluation Levels (EAL)

The Common Criteria (CC) standard defines seven Evaluation Assurance Levels (EALs).

---

## EAL1 – Functionally Tested

### Characteristics

* Basic testing performed.
* Low assurance.

### Suitable For

Products requiring minimal security confidence.

### Keyword

**Tested**

---

## EAL2 – Structurally Tested

### Characteristics

* Design information reviewed.
* Moderate testing.

### Suitable For

Commercial products.

### Keyword

**Reviewed Design**

---

## EAL3 – Methodically Tested and Checked

### Characteristics

* Systematic testing.
* Development environment examined.

### Suitable For

Products needing moderate assurance.

### Keyword

**Methodical Testing**

---

## EAL4 – Methodically Designed, Tested and Reviewed

### Characteristics

* Comprehensive review.
* Strong assurance.

### Suitable For

Most commercial security products.

### Keyword

**Most Common Level**

---

## EAL5 – Semiformally Designed and Tested

### Characteristics

* Rigorous design analysis.
* Advanced testing.

### Suitable For

High-security environments.

### Keyword

**Semiformal Design**

---

## EAL6 – Semiformally Verified, Designed and Tested

### Characteristics

* Extensive verification.
* Very high assurance.

### Suitable For

Critical government systems.

### Keyword

**High Assurance**

---

## EAL7 – Formally Verified, Designed and Tested

### Characteristics

* Formal mathematical verification.
* Highest assurance level.

### Suitable For

Military and highly critical systems.

### Keyword

**Formal Verification**

# 6. Evaluation Methodology

Evaluation Methodology is the structured approach used to assess security properties of a system.

---

## Main Components

### 1. Security Target (ST)

Defines:

* Security objectives.
* Security requirements.
* Evaluation scope.

---

### 2. Protection Profile (PP)

Defines standardized security requirements for a product category.

Examples:

* Firewall PP
* Smart Card PP

---

### 3. Testing

Includes:

* Functional Testing
* Penetration Testing
* Vulnerability Analysis

---

### 4. Evidence Review

Review:

* Design documents
* Source code
* Test reports
* Configuration records

---

### 5. Assurance Validation

Verify:

* Security controls.
* Development process.
* Operational procedures.

---

# Common Criteria (CC)

The most widely used international standard for security evaluation.

### Full Form

**Common Criteria for Information Technology Security Evaluation**

### Standard

**ISO/IEC 15408**

### Purpose

Provides a framework to:

* Specify security requirements.
* Evaluate products.
* Assign EAL levels.
