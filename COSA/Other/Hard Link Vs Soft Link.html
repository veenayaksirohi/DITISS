📄 🔗 Hard Link vs Soft (Symbolic) Link — Cheat Sheet

🧠 Core Idea

🔵 Hard Link = Same file, multiple names (same inode)

🟢 Soft Link = Shortcut → points to file path

📌 Definitions

🔵 Hard Link

  • Another name for the same inode (file data)
  • Directly points to actual data on disk

🟢 Soft (Symbolic) Link

  • A file that stores path of another file
  • Acts like a shortcut

🔑 Must-Remember Points

📌 Inode

  • Stores metadata (NOT filename)
  • Hard links share same inode

📌 Link Count

  • File deleted only when:
link count = 0

📌 Dangling Link

  • Soft link breaks if original file is removed

🛠️ Commands

# Hard Link
ln file.txt hard.txt

# Soft Link
ln -s file.txt soft.txt

# Check inode
ls -li

# Detailed info
stat file.txt

🧪 Quick Example

echo "Hello" > file.txt
ln file.txt hard.txt
ln -s file.txt soft.txt
rm file.txt

👉 Result:

  • hard.txt ✅ works
  • soft.txt ❌ broken

🎯 Use Cases

🔵 Hard Link

  • Backup without duplicating data
  • Save disk space

🟢 Soft Link

  • Shortcuts (like Windows)
  • Link configs across directories
  • Cross-filesystem linking

📌 Analogy

  • 🔵 Hard Link → Same book, different names
  • 🟢 Soft Link → Bookmark to a book

🔥 Final Takeaway

✅ Hard Link → Same data (inode)

✅ Soft Link → Pointer (path)
