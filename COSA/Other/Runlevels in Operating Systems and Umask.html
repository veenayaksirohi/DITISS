Runlevels in Operating Systems

Runlevels are a concept (mainly from traditional UNIX and early Linux systems) that define the state of a machine after boot, i.e., what services and processes are running.

Think of a runlevel as a mode of operation for the OS.

Traditional Linux Runlevels (SysV init)

RunlevelMeaning
0Shutdown / Halt system
1Single-user mode (recovery mode, no networking)
2Multi-user mode (without networking in some distros)
3Full multi-user mode (CLI, networking enabled)
4Unused / user-defined
5Multi-user mode with GUI (desktop environment)
6Reboot system

Easy Memory Trick

  • 0 = Off
  • 1 = Rescue
  • 3 = Server mode (CLI)
  • 5 = Desktop mode (GUI)
  • 6 = Restart

How runlevels work

  1. Kernel starts
  2. init (or systemd) decides the runlevel
  3. System starts services assigned to that runlevel

What is umask in Operating Systems

umask (User Mask) defines the default permission settings for newly created files and directories.

It does not give permissions it removes (masks) permissions from the system’s default.

Default Permissions

  • Files → 666 → rw-rw-rw-
  • Directories → 777 → rwxrwxrwx

Formula

Final Permission = Default Permission - umask

Examples

umask = 022

  • Files → 644 → rw-r--r--
  • Directories → 755 → rwxr-xr-x

umask = 077

  • Files → 600 → rw-------
  • Directories → 700 → rwx------

Key Concept

umask removes permissions

umask bitMeaning
0allow permission
1remove permission

Important Notes

  • umask cannot add permissions only remove
  • Affects new files only
  • Execute bit for files is not given by default
