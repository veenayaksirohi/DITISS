8. cat — Create and Display File

Definition:
cat (concatenate) is used to create, display, and combine files.

  1. 📄 cat is a Linux command used to display or read files.
  2. ⌨️ When used without a file, it takes input from the keyboard.
  3. ⏳ It keeps running until it receives EOF (End Of File).
  4. 🔚 EOF is sent using Ctrl + D in the terminal.
  5. 🛑 After receiving EOF, cat stops and exits.
  6. ⚙️ cat does not generate EOF; it only responds to it.

Important Options ⭐

cat filename
Display file content 
cat file.txt
cat > filename
Create new file and write content 
cat > file.txt
cat >> filename
Append text to existing file 
cat >> file.txt
cat -n filename
Show line numbers

Extra Inputs 🧠

  • > overwrites file
  • >> adds content without deleting old data

10. cp — Copy Files and Directories

Definition:
cp copies files or directories.

Important Options ⭐

cp file1 file2
Copy file 
cp -r dir1 dir2
Copy directory recursively 
cp -i
Ask before overwrite Linux cp -i Command Notes

1. Introduction

The cp command in Linux is used to copy files and directories. The -i option enables interactive mode, which asks for confirmation before overwriting existing files.

2. Syntax

cp -i source_file destination_file

3. Working of cp -i

When you use cp -i, the system checks if the destination file already exists. If it does, it prompts the user before overwriting.

Example prompt:
cp: overwrite 'file.txt'?

4. User Response Options

  • y → overwrite the file
  • n → do not overwrite

5. Example Usage

Copying a file:

cp -i notes.txt backup.txt

If backup.txt already exists, the system will ask for confirmation before replacing it.

6. Advantages

  • Prevents accidental file overwriting
  • Gives user control during copying
  • Useful in system administration

7. Disadvantages

  • Can slow down bulk file copying due to prompts
  • Not suitable for automated scripts

8. Comparison with Other cp Options

  • cp -i → asks before overwrite (safe)
  • cp -f → forces overwrite without asking
  • cp -n → never overwrite existing files

9. Summary

cp -i is a safety feature in Linux that ensures you do not accidentally overwrite important files by asking for confirmation before replacing them. 

cp -v
Show copying process

Extra Inputs 🧠

cp -r directory
Required for copying directories.

Linux Commands Notes — Part 6 (rm Safety & Dangerous Commands)

Linux Commands Notes — rm Safety & Dangerous Commands

Understanding These rm Commands

You wrote several variations — here’s what each one actually does and whether it is valid or dangerous ⚠️.

1️⃣ rm * in pwd

Meaning:
Deletes all files in the current working directory. 

rm *
  • * → matches all files
  • Works in the directory shown by pwd
  • Deletes files only, not directories (unless -r used)

⚠️ Danger Level: High
All files in current directory will be deleted.

2️⃣ rm * in cd ~

This means:

cd ~
rm *

Meaning:
Deletes all files in your home directory.

⚠️ Danger Level: Very High
You may delete personal files.

3️⃣ sudo rm * in pwd

sudo rm *

Meaning:
Deletes all files in current directory using administrator (root) privileges.

  • sudo → runs command as root
  • Can delete protected files

⚠️ Danger Level: Very High
Can delete system-important files.

4️⃣ sudo rm * cd ~ ❌ (Invalid Command)

This command is not correct syntax.

sudo rm * cd ~

❌ This will produce an error.

Correct way would be:

cd ~
sudo rm *

Important Related Options ⭐

Command Meaning
rm * Delete all files
rm -r * Delete files + directories
rm -rf * Force delete everything ⚠️ Very dangerous
rm -i * Ask before deleting

Very Important Safety Warning ⚠️

These are extremely dangerous commands: 
rm -rf *
sudo rm -rf /
They can:
  • Delete entire system
  • Make Linux unusable

⭐ Exam Tip

  • * → Means all files
  • sudo → Means admin/root privileges
  • rm -r → Required to delete directories
  • cd ~ → Moves to home directory

Linux Commands Notes — Part F (kill System Call & Signals)

kill System Call — IPC Mechanism to Send Signals

Definition of kill() System Call

The kill() system call is an Inter-Process Communication (IPC) mechanism used to send signals from one process to another process.

It is commonly used to:

  • Stop a running process
  • Control process behavior
  • Send signals between processes

Basic Syntax of kill System Call

kill(pid_t pid, int signal);
Where:
  • pid → Process ID
  • signal → Signal number sent to process

kill Command vs kill System Call

Feature kill Command kill() System Call
Type User command System call
Usage Terminal command Used in programs
Purpose Send signals Send signals
Example 
kill 1234
 
kill(pid, SIGKILL);

Important Signals ⭐

Signal Name Number Description
SIGTERM 15 Terminate process (default signal)
SIGKILL 9 Forcefully kill process
SIGSTOP 19 Stop (pause) process
SIGCONT 18 Continue stopped process
SIGINT 2 Interrupt process (Ctrl + C)

Examples of kill Command

Terminate normally: 
kill 1234
Force terminate: 
kill -9 1234
Stop process: 
kill -19 1234
Continue stopped process: 
kill -18 1234

Extra Notes 🧠

  • Use ps command to find PID.
    • ps aux
  • Default signal of kill = SIGTERM
  • Best practice:
    • Use SIGTERM first
    • Use SIGKILL only if needed
⚠️ Important Safety Note Using SIGKILL (-9) may:
  • Cause data loss
  • Corrupt files
  • Stop critical services

⭐ Exam Important Points

  • kill() is an IPC mechanism
  • Used to send signals
  • Most important signals:
    • SIGTERM (15)
    • SIGKILL (9)
    • SIGSTOP (19)
    • SIGCONT (18)

Linux Commands Notes — Part H (Synchronous vs Asynchronous Execution)

Synchronous vs Asynchronous Execution

Synchronous Execution

Definition:
Synchronous execution means that one command runs at a time. The next command starts only after the previous command finishes.

Example

ls
pwd
date
Explanation:
  • First ls runs
  • After completion → pwd runs
  • Then → date runs
Extra Notes 🧠
  • This is the default execution mode
  • Most commands run synchronously
  • Also called Foreground Execution

Asynchronous Execution

Definition:
Asynchronous execution means that multiple commands run simultaneously. The shell does not wait for the previous command to finish.

Syntax

command &

Example

sleep 10 &
Explanation:
  • Command runs in background
  • Terminal becomes free immediately
  • User can run another command
Extra Notes 🧠
  • & symbol sends process to background
  • Also called Background Execution
  • Very useful for:
    • Long-running tasks
    • Downloads
    • Server processes

Foreground vs Background Execution

Execution Type Description
Foreground Command runs in front and blocks terminal
Background Command runs in background and frees terminal

Synchronous vs Asynchronous ⭐

Feature Synchronous Asynchronous
Execution One at a time Multiple simultaneously
Waiting Waits to finish Does not wait
Terminal Blocked Free
Operator None &
Also Called Foreground Background

⭐ Exam Important Points

  • Synchronous → Foreground execution
  • Asynchronous → Background execution
  • & → Background operator
  • Default execution = Synchronous
  • Very common exam question
